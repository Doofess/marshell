# Stuck detection and the terminal attention fallback (slice 4d) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sessions without hooks get attention from BEL, OSC 9 and OSC 777. Hooked agents that repeat one tool call or go quiet while Working show as stuck.

**Architecture:**
- The pty scanner learns two new marks: a terminal notification and a bare bell. The registry turns them into a new `SessionInfo.attention`, which is gated on hook status, foreground and recent typing.
- The notify engine treats attention as a needs-you wait.
- A pure `StuckTracker` per session watches Claude's hook events. A 30 s tick in the core checks it and sets a new `SessionInfo.stuck`.
- The frontend maps attention to a needs-question row and stuck to the existing dashed-ring glyph.

**Tech Stack:** Rust (tokio, serde, ts-rs), React + TypeScript, Vitest.

**Spec:** `docs/PLAN.md` §9, "Slice 4d decisions (2026-10-23)". Also the status table in PLAN §"Status vocabulary" (the Stuck row) and brief §5.5 ("Fallback for CLIs without hooks").

## Global Constraints

- No new dependencies (`SCOPE.md`). The CSP is never loosened.
- `src/generated/` is regenerated by `cargo test -p marshell-protocol` and never hand-edited. Every `u64` in the protocol carries `#[ts(type = "number")]` (or `"number | null"`), because `pnpm check:generated` fails on `bigint`.
- Run `cargo fmt --all` before each Rust commit. Commit messages read `type(scope): sentence` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Copy is exact:
  - the attention fallback: "Wants your attention";
  - stuck from repeats: "Same command 9× in 4 min";
  - stuck from quiet: "No progress for 10 min";
  - the switch: "Alerts from terminal programs (bell, OSC 9, OSC 777)".
- Thresholds are exact: a bare BEL is ignored within 1 s of typing; repeats count 9 identical calls in 4 min; quiet is 10 min with no hook event.
- Stuck raises no notification and adds nothing to any count. Attention counts exactly like needs-you.
- The fallback never acts on a session with hook status (`info.live.is_some()`).
- Windows 11 is the tested platform; nothing here is platform-specific.

## Review Focus

1. **BEL that isn't a bell.** A BEL ending an OSC 0/2 title, an OSC 8 link, a DCS or APC string, or any sequence split across two reads must not count. `ESC]9;9;…` (ConEmu cwd) and `ESC]9;4;…` (Windows Terminal progress) are not notifications. Task 2 tests each case.
2. **A hooked session rings.** Claude Code with hooks rings BEL or sends OSC 9: nothing changes. Task 3 tests it.
3. **Typing echo.** A shell rings BEL 200 ms after a keystroke: ignored. A program rings 2 s after the last keystroke: it counts. Task 3 tests both with an injected clock.
4. **A flood.** `type` on a binary file rings 500 bells. That is one attention, one wait and one banner: `since_ms` stays at the first bell until the attention clears. Tasks 3 and 4 test it.
5. **Stuck noise.** `PostToolUse`, `Notification` and status line updates between identical `PreToolUse` calls don't reset the count, and status line updates don't count as progress. Quiet stuck never fires outside Working. A session that ends clears its tracker. Task 5 tests each.
6. **Pop-outs keep the focus (added mid-slice at the user's request).** While a menu, the launcher, the palette, the layout popover, a key-opened peek or a dialog is open, focus that lands outside it (Tab past the last control, a terminal focused by a timer or a banner click, nothing after the window lost focus) comes back to it, and Tab wraps inside it. It must never fight: a dialog opened over a menu keeps its focus, an opener's refocus or Rename's box after a close is not pulled back, and two open pop-outs don't trade the focus. The row menu's Tab still closes it (PLAN §9). `src/lib/focusGuard.test.ts` covers the guard; the wiring is checked live.

### Task 3: The registry turns signals into attention

**Files:**
- Modify: `crates/core/src/registry.rs` (`Entry` ~30-52, `mark` ~434-461, new functions, tests)
- Modify: `crates/core/src/server/pty_ws.rs` (~79-87) and `crates/core/src/server/sessions.rs` (`input` ~486-498): call `note_input`
- Modify: `crates/core/src/server/view.rs` (`put`) or `server/mod.rs` `report_view` (~308): call `clear_attention_seen`

**Interfaces:**
- Consumes: `Mark::Notify`, `Mark::Bell` (Task 2), `SessionInfo.attention` (Task 1).
- Produces:
  - `Registry::note_input(&self, tab_id: &str)`: records `Instant::now()` in `Entry.last_input` and clears `attention`.
  - `Registry::clear_attention_seen(&self, view: &UiView)`: when `view.window_focused`, clears `attention` on every tab in `view.visible_tabs`.
  - `mark()` handles `Mark::Notify(msg)` and `Mark::Bell` through a pure `fn attention_allowed(info: &SessionInfo, bell: bool, last_input: Option<Instant>, now: Instant) -> bool`.
    - It returns false when `info.live.is_some()`.
    - For a bell it also returns false unless `info.command == CommandState::Running || info.foreground.is_some()`, and false when `now - last_input < 1 s`.
    - An allowed signal sets `attention = Some(Attention { message, since_ms: now_ms })`. If attention is already set, it is kept unchanged, so a flood is one attention. A later `Notify` with a message fills in a missing message without moving `since_ms`.

Clock injection: tests call `attention_allowed` with explicit `Instant`s. `mark` uses `Instant::now()`.

  - Registry: `notify_mark_sets_attention_once` (three marks → one `since_ms`); `note_input_clears_attention`; `focused_view_clears_visible_attention` and `unfocused_view_keeps_it`.

### Task 5: Stuck detection

**Files:**
- Create: `crates/core/src/stuck.rs` (`StuckTracker`, unit tests), register it in `crates/core/src/lib.rs`
- Modify: `crates/core/src/registry.rs` (`Entry.stuck: StuckTracker`, new functions)
- Modify: `crates/core/src/server/hook.rs` (~157: feed each Claude hook body to the tracker)
- Modify: `crates/core/src/server/mod.rs` (spawn the 30 s tick; `MARSHELL_STUCK_QUIET_SECS` override, clamped to 5..=3600, next to the `MARSHELL_PERMISSION_HOLD_SECS` reader ~630-664)

**Interfaces:**
- Consumes: `Stuck`, `StuckReason` (Task 1).
- Produces:
  - `pub struct StuckTracker`. It holds the last 4 min of `PreToolUse` keys as `(ms, String)`, where a key is `tool_name` plus `tool_input` serialised with sorted keys. It also holds `last_event_ms` and `repeat_since: Option<u64>`.
  - `StuckTracker::on_event(&mut self, body: &serde_json::Value, now_ms: u64) -> Option<Stuck>`. Every hook event updates `last_event_ms`. A `PreToolUse` whose key appears 9+ times in the window returns `Some(Stuck { reason: Repeat, since_ms })`, where `since_ms` stays at the 9th call. A `PreToolUse` with a different key, or a `UserPromptSubmit`, clears the window's verdict and returns `None`. Other events return the current verdict unchanged.
  - `StuckTracker::quiet(&self, working: bool, now_ms: u64, quiet_ms: u64) -> Option<Stuck>`: `Some(Quiet)` when `working` and `now_ms - last_event_ms >= quiet_ms`.
  - `Registry::stuck_event(&self, tab_id: &str, body: &Value, now_ms: u64)` and `Registry::check_stuck(&self, now_ms: u64, quiet_ms: u64)`. These set `info.stuck`, Repeat taking precedence over Quiet, and broadcast only on a change.
  - Whenever `live.state` leaves `Working` through `update_live` or `settle_done`, `stuck` becomes `None`. A session that ends drops its tracker.
  - Status line updates (`fold_statusline`) never reach the tracker.
