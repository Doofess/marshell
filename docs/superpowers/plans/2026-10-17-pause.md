# Pause Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pause freezes a running session's whole process tree, Continue thaws it, and the row shows Paused while it is frozen.

**Architecture:** A new core module `pty/freeze.rs` freezes a process tree.
- **Windows:** it walks the tree from the session's pid with a Toolhelp snapshot and calls `SuspendThread` on every thread it finds. It records the thread ids so that Continue resumes exactly those threads.
- **Unix:** it sends `killpg(SIGSTOP)` to the session's process group and `killpg(SIGCONT)` to thaw it.

`pty::Session` owns the frozen state. Two new routes flip it, and a `paused` flag on `SessionInfo` carries it to the frontend. The frontend adds a Paused glyph, Pause and Continue in the row menu and the palette, a first-time confirm bar, and a "Paused. Continue to type." bar when someone types into a paused session.

**Tech Stack:** Rust (portable-pty, windows-sys 0.61, libc), axum, ts-rs, React, TypeScript, Vitest.

**Spec:** `docs/PLAN.md` line ~828 (the row menu: "Pause in its own PR"), and the user's answers of 2026-10-17:
- Pause freezes the whole process tree, using a Job Object or thread suspend on Windows and SIGSTOP elsewhere, with a Paused mark and a one-time network warning.
- The item that unfreezes is called **Continue**. Resume keeps its meaning: start an ended agent again.
- Typing into a paused session sends nothing and shows an inline bar in the pane: "Paused. Continue to type." with a Continue button.
- Any running session can be paused, a plain shell as well as an agent.
- The first Pause ever shows an inline confirm with the network warning. Later Pauses act at once.

## Global Constraints

- No new crates. Add the feature `Win32_System_Diagnostics_ToolHelp` to the existing `windows-sys` line in `crates/core/Cargo.toml`. The line becomes `features = ["Win32_Foundation", "Win32_Security", "Win32_System_Diagnostics_ToolHelp", "Win32_System_JobObjects", "Win32_System_Threading"]`.
- Every `unsafe` block has a `// SAFETY:` line, as in `crates/core/src/job.rs`.
- Status values are never guessed. A session is shown as Paused only after every thread in its tree was suspended. If any thread could not be suspended, everything is thawed and the pause is refused.
- Copy:
  - Menu and palette: "Pause", "Continue", "Pause session" and "Continue session".
  - Glyph label: "Paused".
  - Confirm bar: "Pause {n} {name}? It freezes the program and everything it started. Network connections can time out while it's paused." with the buttons "Cancel" and "Pause".
  - Typing bar: "Paused. Continue to type." with the button "Continue".
  - Refusal toast: "Couldn't pause the session: {reason}" or "Couldn't continue the session: {reason}".
  - Core reasons: "Only a running session can be paused." and "Part of it can't be paused, such as a program running as administrator."
- Keep `pnpm check:generated` consistent after the protocol changes.
- Non-applicable menu items are omitted, never disabled (`sessionMenu.ts:16`).

## Review Focus

1. **Closing, restarting or quitting while paused.** A frozen tree must still end. On Unix a stopped process does not act on SIGHUP until it gets SIGCONT, so `kill` thaws first. On quit, nothing may be left suspended, because `release_children` lets user programs outlive Marshell. Task 1 tests `kill_ends_a_frozen_session`.
2. **A child started during the walk.** On Windows, a process created while the tree is being suspended must be caught. The walk repeats until a pass finds no new thread, at most 5 passes. Task 1 tests `freeze_stops_a_grandchild`.
3. **PID reuse.** On Windows, an orphan whose recorded parent pid now belongs to a process in our tree must not be frozen. A child counts only if its creation time is later than its parent's. This is reviewer-checked: no test is possible.
4. **Exit while paused.** If something outside Marshell kills a frozen session, the row goes to Exited and `paused` is false. Task 2 tests `exit_clears_paused`.
5. **Keys while paused.** The WebSocket path drops input in core, the POST input route returns 409, and the frontend never sends. Task 2 tests `input_refused_while_paused`, and Task 3 tests `blockedInput`.

### Task 1: Freeze a session's process tree (core)

**Files:**

- Modify:

- Test: `crates/core/tests/session.rs` (where `kill_takes_the_tree` lives).

**Interfaces:**
- Produces:
  - `pub enum FreezeError { NotRunning, Partial }`, implementing `Display` with exactly the two core reasons from Global Constraints.
  - `impl Session { pub fn freeze(&self) -> Result<(), FreezeError>; pub fn thaw(&self); pub fn is_frozen(&self) -> bool }`.
  - `freeze` on a frozen session returns `Ok(())` and does nothing. `thaw` on a session that isn't frozen does nothing. `freeze` after exit returns `Err(NotRunning)`.

- [ ] **Step 1: Write the failing tests** in `crates/core/tests/session.rs`. Use the spawn helpers that `kill_takes_the_tree` uses.
  - `freeze_stops_output`: start a session that prints a line every 100 ms (`ping -t 127.0.0.1` on Windows, `sh -c 'while :; do echo x; sleep 0.1; done'` on Unix). Wait for output. Call `freeze()`. Wait 300 ms to settle, record the output length, wait 1.5 s, and assert the length is unchanged and `is_frozen()`. Call `thaw()`, then assert the output grows within 3 s and `!is_frozen()`.
  - `freeze_stops_a_grandchild`: the same, but the printer is a grandchild (Windows `cmd /c "cmd /c ping -t 127.0.0.1"`, Unix `sh -c 'sh -c "while :; do echo x; sleep 0.1; done"'`).
  - `kill_ends_a_frozen_session`: freeze, call `kill()`, and assert the exit callback fires within 5 s.
  - `freeze_after_exit_is_refused`: let a short command exit, then assert `freeze()` returns `Err(FreezeError::NotRunning)`.
- [ ] **Step 2: Run `cargo test -p marshell-core --test session freeze`.** Expected: fails to compile (`freeze` is not defined).
- [ ] **Step 3: Implement `freeze.rs`.**
  - **Windows:** `pub(crate) fn suspend_tree(root: u32) -> Result<Vec<u32>, ()>` and `pub(crate) fn resume_threads(threads: &[u32])`.
    - The walk:
      - take a `TH32CS_SNAPPROCESS` snapshot;
      - collect the descendants of `root` through `th32ParentProcessID`, where a child counts only if its `GetProcessTimes` creation time is later than its parent's (Review Focus 3);
      - take a `TH32CS_SNAPTHREAD` snapshot and call `OpenThread(THREAD_SUSPEND_RESUME)` and then `SuspendThread` on each thread whose owner is in the set and that isn't suspended already by us.
    - Repeat the walk until a pass adds no thread, at most 5 passes.
    - If any `OpenThread` or `SuspendThread` fails, call `resume_threads` on what was done and return `Err(())`.
    - Close every handle.
  - **Unix:** `killpg(pid, SIGSTOP)` and `killpg(pid, SIGCONT)`.
- [ ] **Step 4: Implement it in `Session`.**
  - Add `frozen: Mutex<Option<Frozen>>`, where `Frozen` holds the thread ids on Windows and nothing on Unix.
  - `freeze` checks `exited` and returns `NotRunning` if set. `Partial` comes from `Err(())`.
  - `kill` and `force_kill` call `thaw()` before the existing kill. On Unix, `kill_tree` also sends `SIGCONT` right after `SIGHUP` so the hang-up is acted on.
  - `on_exit` clears `frozen` without resuming anything, since the threads are gone.
- [ ] **Step 5: Run `cargo test -p marshell-core --test session`.** Expected: all pass, the four new tests included.
- [ ] **Step 6: Commit** with `feat(core): freeze and thaw a session's whole process tree`.
