# Phase 2.5a: Preview, Clickable Paths and Quick Open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only preview pane for code, Markdown, images and HTML. It opens with Ctrl+click on a file path in any terminal's output, or from quick open in the palette. It sits beside the focused session and reloads when the file changes.

**Architecture:**
- **Core.** Shells already report their folder: `OSC 9;9` from PowerShell and cmd, `OSC 7` from bash. The core starts tracking it per session. A new `server/files.rs` adds four token-checked routes:
  - resolve candidate paths for a session;
  - stat a file;
  - read a file's bytes, capped;
  - list a session's folder for quick open.
- **Frontend.** A new `src/features/preview/` module:
  - a pure state model with history;
  - a view per kind: code and text through lazy Shiki, Markdown through markdown-it and DOMPurify, images through blob URLs, HTML in a sandboxed iframe.
  - **Layout.** `MainWindow` shows the focused session and the preview side by side in place of the split. Closing the preview brings the split back.
  - **Terminal paths.** An xterm link provider finds paths in terminal output.
  - **Quick open.** The palette gains a mixed "Files in <folder>" group and an "Open file…" mode.

**Tech Stack:**
- Rust core: axum and tokio, with no new Rust dependency in the core.
- Tauri 2: `tauri-plugin-opener`, for web links only.
- Frontend: React, TypeScript and xterm.js.
- New frontend libraries: `shiki` (lazy-loaded, JavaScript regex engine), `markdown-it` and `dompurify`.
- Tests: Vitest in the node environment.

**Spec:**
- `docs/PLAN.md` §2.5, lines 836–852: the preview pane, its layout, its security and the new dependencies. Region-to-prompt and PDF belong to 2.5b; paste, drop and capture to 2.5c.
- The 2026-10-17 slice split, from the BRIEF amendments: 2.5a is preview, paths and quick open. Quick open is a palette mode, and Shiki is lazy-loaded.
- The user's 2026-10-17 answers for 2.5a:
  - The preview toggles with Ctrl+Shift+Q.
  - A path opens with Ctrl+click, and only a path that exists becomes a link. Quick open lists paths seen in the output first, for keyboard use.
  - Quick open is a mixed "Files in <folder>" group after 2+ characters, plus an "Open file…" command that shows files only.
  - The preview reads any file the user can read, through the token API. Regular files only. Caps are 2 MB for text and 20 MB for images.
  - File drop moves to 2.5c.
  - A relative path resolves against the shell's current folder, then the launch folder, then the project root.
  - A changed file reloads automatically and keeps its scroll position.
  - Doc links: a local link opens in the preview with Back, a web link asks before opening the browser, and an anchor scrolls.

## Global Constraints

- **Dependencies.** Only these new ones are allowed:
  - frontend: `shiki`, `markdown-it`, `dompurify`, `@tauri-apps/plugin-opener`, and `@types/markdown-it` as a dev dependency;
  - Rust, in `src-tauri` only: `tauri-plugin-opener`.
- **Shiki stays lazy and CSP-safe.** It is reached only through dynamic `import()`, so it never lands in the main chunk. It uses `shiki/core` with `createJavaScriptRegexEngine`, never the WASM engine, so the CSP keeps out `wasm-unsafe-eval`. Languages load per file from the `bundledLanguages` lazy map.
- **CSP.** The only change in `src-tauri/tauri.conf.json` is `blob:` added to `img-src`. Nothing else in the CSP changes.
- **Delivery rule.** Nothing in this slice types into a terminal or fills a prompt line.
- **Caps.** Defined once in the core (`files.rs`) and mirrored in one frontend constant:
  - text 2 MB (2 × 1024 × 1024 bytes); image 20 MB;
  - resolve takes at most 64 candidates of 1024 chars each;
  - the folder list stops at 20 000 files, which sets `truncated`.
- **Path safety.** Before any filesystem call, the core rejects UNC paths (`\\server\…`), device paths (`\\?\`, `\\.\`) and Windows reserved device names (`CON`, `NUL`, `COM1`…). Touching a UNC path would leak the user's NTLM hash to that server, and resolve runs on mouse hover. Only regular files are read or listed, after following symlinks.
- **Shortcut.** The preview toggle is `Ctrl+Shift+Q`. On macOS, `⌘Q` is Quit, so the binding gains an optional `mac` override and the preview uses `⌘⌥Q` there (macOS is untested). Ctrl+click is Cmd+click on macOS.
- **Copy:**
  - "Ctrl+click to preview" (macOS: "⌘+click to preview").
  - "Open file…"
  - "Files in <folder name>"
  - "Seen in output"
  - "This file is too large to preview (<size>, limit <cap>)."
  - "This file isn't text."
  - "PDF preview comes in a later update."
  - "This file was deleted."
  - "Open <url> in your browser?" with Open and Cancel.
  - "Updated"
- **Look.** Every style follows the `frontend-design` skill and the design tokens in `src/styles/`. Read the `good-css` skill before writing declarations, if it is installed. The preview uses the vendor-neutral Sand accent, never a vendor colour.
- **Accessibility.**
  - Everything works from the keyboard.
  - The preview is a labelled region: "Preview, <file name>".
  - Its body is a focusable scroll container.
  - Esc in the preview returns focus to the session's terminal without closing it.
  - Alt+Left goes Back.
  - The "Updated" note is not announced unless focus is in the preview.
- **Tests.** Vitest runs in the node environment, with no DOM. UI behaviour is tested through pure modules and `renderToStaticMarkup`, as the existing tests do. Rust routes get integration tests in `crates/core/tests/files.rs`.

## Review Focus

1. **A hostile program prints `\\attacker\share\a.txt`.** Hover and Ctrl+click must never touch the network: resolve, stat and content all refuse UNC and device paths before any I/O. Task 2 tests each route with such paths.
2. **A path wraps across two terminal rows, or the line holds wide (CJK) characters.** The link covers the right cells, and the candidate is the whole path. Task 5 tests the offset mapping with a wrapped line and a wide character.
3. **An HTML file with `<meta http-equiv="refresh">`, a remote `<img>`, `<iframe>`, `<form>` or `<script>`.** None of them loads anything or runs: the iframe is sandboxed without `allow-scripts`, its injected CSP is `default-src 'none'`, and refresh metas are stripped. Task 4 tests the srcdoc builder.
4. **A narrow window.** With under 720 px of main width, the preview takes the whole main area and the session keeps running behind it. Closing the preview brings back exactly the split that was there before. Task 3 tests the layout choice.
5. **A file that changes, grows past its cap, or is deleted while it is previewed.** It reloads, shows the too-large message, or shows "This file was deleted." over the last content. It never throws, and polling stops while the preview is closed. Task 3 tests the reload state machine.

### Task 2: The files API

**Files:**
- Create: `crates/core/src/server/files.rs`
- Modify: `crates/core/src/server/mod.rs` (routes)
- Modify: `crates/protocol/src/api.rs` (types); regenerate with `cargo test -p marshell-protocol`
- Test: `crates/core/tests/files.rs`, plus unit tests in `files.rs`

**Interfaces:**
- Consumes: `Session::current_cwd()` from Task 1; `SessionInfo.cwd` and `.project`; `crates/core/src/git.rs` for running git.
- Produces (all under the existing auth guard):
  - `POST /v1/sessions/{tab}/resolve`, body `ResolveRequest { candidates: Vec<String> }`, returns `ResolveResponse { paths: Vec<Option<String>> }`.
    - One entry per candidate: the absolute path of an existing regular file, or null.
    - An unknown tab is 404. Over 64 candidates, or one over 1024 chars, is 400.
  - `GET /v1/files/stat?path=<abs>` returns `FileStat { size: u64, modified_ms: u64 }`.
    - A missing path or a non-file is 404. A refused path (see Path safety) is 400.
  - `GET /v1/files/content?path=<abs>&kind=text|image` returns the raw bytes.
    - The `Content-Type` comes from the extension (`application/octet-stream` when unknown), and an `X-Modified-Ms` header is set.
    - Over the kind's cap is 413, with a JSON body `{ size, limit }`.
  - `GET /v1/sessions/{tab}/files` returns `FileList { root: String, files: Vec<String>, truncated: bool }`.
    - `files` are relative paths with `/` separators.
  - Rust helper `fn refused(path: &str) -> bool` (the safety check), shared by every route.

  - false: `C:\a\b.rs`, `C:/a/b.rs`, `/home/u/a`, `src/a.rs`.
