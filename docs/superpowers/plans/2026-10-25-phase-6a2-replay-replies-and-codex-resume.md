# Slice 6a2: no replies to replayed queries, and Codex resumes its own conversation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tab first shown after its CLI started no longer gets xterm's late answer to a colour query typed into the CLI (#60), and Resume and Restart of a Codex tab pick up that tab's own conversation (#61).

**Architecture:** #60: after each Resume, the core's pty WebSocket sends a new `LIVE` frame carrying the byte offset where live output starts, and caps the replay at that offset. The terminal drops the replies xterm generates while it parses bytes before that offset, through a small pure gate. Typing, focus, mouse and replies to live queries pass as before. #61: `resume_session` gives a Codex tab `Resume::Session(id)` for its latest Codex conversation on record, with the same id and path check History's "Open in new tab" uses. `resume_args` already turns that into `codex resume <id>`.

**Tech stack:** Rust (axum WebSocket, the pty session), TypeScript (xterm.js 6, `PtySocket`), Vitest in a node environment, `cargo test`.

**Spec:** `docs/PLAN.md` §9, "Slice 6a2 decisions (2026-10-25)", items 1–4. Evidence: issues #60 and #61, and `docs/research/2026-10-24-codex-adapter-live-check.md` findings 5 and 12.

## Global constraints

- No new dependency, on either side.
- The frame protocol stays backward-compatible. An older frontend ignores an unknown server frame (`decodeServerFrame` returns null), and the new frame changes nothing it relies on.
- `src/generated/` is regenerated by `cargo test -p marshell-protocol` and never edited by hand. `pnpm check:generated` must pass.
- No change to `guard.rs`, the token, or file permissions under the Marshell home (`.claude/rules/local-api.md`).
- Tests never run the real `codex`. Pin `with_codex_version(...)` and `with_agent_path(|_| None)` on any `AppState` that resolves a Codex launch.
- Tests and the live check never read or write the real `~/.codex`, `~/.claude` or `~/.marshell`.
- Out of scope: the Restart bar's copy (`resumeCommand.ts`) keeps showing the CLI's continue form (`codex resume --last`), as it already shows `claude --continue` for a Claude tab the core resumes by id.

## Review focus

1. **Typing while a long replay is parsed** still reaches the CLI. Only replies are gated (Task 2: `typing during the replay passes`).
2. **A live query answered right after the replay** gets its reply sent. The gate opens at exactly the live offset (Task 2: `a reply after the live offset passes`; Task 1 caps the replay so no frame straddles the offset).
3. **A WebSocket reconnect** sends a new `LIVE`, so output written while disconnected is replay and its replies are dropped (Task 2: `a second live frame moves the boundary`).
4. **A bracketed paste that contains an escape sequence** is the person, not a reply (Task 2: `isQueryReply` is false for `\x1b[200~…\x1b[201~`).
5. **A Codex row that fails the id and path check, or a row from another agent** never reaches a command line (Task 3: `a_codex_row_that_fails_the_check_resumes_the_last`, `a_tab_resumes_only_its_own_agents_conversation`).
