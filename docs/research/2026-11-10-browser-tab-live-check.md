# Browser tab live check (slice 6q-3a)

- Date: 2026-11-10, 11:38 to 12:40 local time.
- Build: `phase-6q-3a` under `pnpm tauri dev`, then the release build (`pnpm tauri build --no-bundle`, run from `target\release\marshell-app.exe`), on Windows 11 Pro (10.0.26300) with WebView2 runtime 157.0.4341.42, one display at 100% scale.
- Home: a scratch `MARSHELL_HOME`, `CLAUDE_CONFIG_DIR`, `MARSHELL_CLAUDE_SETTINGS`, `CODEX_HOME`, `COPILOT_HOME` and `USERPROFILE` for each build, with CDP on port 9333. Onboarding was passed with "Skip: use limited status" on every card. No agent CLI was started; the real `~/.claude/settings.json` kept its modified time and nothing under the real `~/.marshell` changed.
- Data: a test site on loopback (`http://127.0.0.1:47620/`, a Node script that is not committed) whose pages report their loads, keys, focus, scroll and colour scheme to its log. PowerShell 7 sessions started by the check in a scratch project, one of them running a second listener on port 47621 for the port chip, and a Markdown file of links.
- How it was driven: CDP evaluations, keys and clicks in the app's own webview. A page has no CDP (S12 finding 2), so a page was read through the site's log, the shell's `browser_capture` picture, UI Automation, and the windows' rects and keyboard focus (`GetWindowRect`, `GetGUIThreadInfo`), all read-only. The window was resized with `SetWindowPos`, which sends no mouse or keyboard input. Emulated light scheme, forced colours and device scale; 4 screenshots. No real key, mouse or drag input was sent: the checks that need it are marked.

## Findings

1. **A refused link or redirect lost its status line at once.** The page reports the end of the cancelled navigation like any other, and that cleared "That address can't be opened in the side pane.". Fixed in `b26362d3`: the line stays until a navigation starts or the address changes (failing-first tests in `pageStore.test.ts`).
2. **Enter in the address box left the keyboard in the box.** Every browser moves it into the page. Changed in `0452089f` (failing-first tests in `BrowserTab.test.tsx`); it stays in the box when the shell refuses the address.
3. **A page unloaded to make room stayed blank when its tab was shown again.** The store still held the closed page, so the tab asked the shell to show a page that no longer existed. Fixed in `7a7653a9` (failing-first tests in `useBrowserPages.test.ts`).
4. **A page that left the screen could be handed the keyboard.** A page keeps its turn at the keyboard while the app borrows it. When a palette command, or anything but a key or a press in the app, took the person to another tab or session, the turn was not ended, and the window coming back to the front gave the keyboard to the hidden page. Fixed in `e86f77d6`: a page that is not on screen never gets it (failing-first tests in `pageFocus.test.ts`), checked live with the window's focus event.
5. **A page hidden while it had the keyboard kept it.** Windows left the focus on the hidden page's window, so typing reached nothing on screen. Fixed in `6ccaf5d4`: when the shell hides a page and the focus is on a window that is not shown, the app's webview takes it. No unit test can hold a window's focus; checked live, where the focus was on the hidden page before and on the app's webview after, for a session switch and a tab switch.
6. **A link to one of the app's own origins leaves an empty tab.** The tab opens, the shell refuses the address, and the tab stays with the status line and no page. Not fixed: the app's webview can't tell its own origins from another loopback address before it asks.
7. **No session shortcut works from the Address box.** A text box keeps its own keys (`LiveApp.tsx`), so Ctrl+Shift+K does nothing there. Not fixed: a product question.
8. **A right-click where the app has no menu of its own opens WebView2's menu** (Back, Refresh, Save as, Print, More tools, Inspect in a debug build), on a pane tab for one. It was there before this slice. Not fixed.
9. **Smaller ones, not fixed.** The palette lists the session rows for an unrelated query. A refused typed address puts the page's address back in the box, while a typed path keeps the text. A `file:` link in a Markdown preview is not a link, and a `file:` link or redirect from a page is stopped by WebView2 itself with no status line (the redirect shows its own error page). A tab named "New tab" and the strip's "New tab" button share a name. In a debug build Tauri's refusal names the capability and permission to a page; the release build doesn't.
10. **For the next live check.** A release build started with a scratch `USERPROFILE` that has no `AppData\Local` keeps the app's own webview data beside the exe, and WebView2 then ignores the debugging port. A CDP right-click leaves WebView2's menu open on the desktop until its window is closed.
