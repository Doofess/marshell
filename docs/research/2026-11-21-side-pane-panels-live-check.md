## Findings

1. **A divider move could end 1 px from where it was put.** A move saves weights for two whole heights, and `stackHeights` rounded the shares back by giving every spare pixel to the first panel, so some positions came back one pixel off (470 and 269 in a 740 px pane, for one). Fixed in `610b8dfa`: the spare pixel goes to the panel that lost the most to the rounding. Failing first: `stackLayout.test.ts`, "gives back the heights a divider move asked for, at every position" and "a spare pixel goes to the panel that is furthest from its share, and to the first on a tie".
2. **A key pressed inside a rendered HTML file never reached the app.** The file is a frame with its own document, and the app's shortcuts listen on the window, so Ctrl+Shift+A, D, Q, Ctrl+Shift+Tab and Ctrl+Tab did nothing there. That is older than this slice (the HTML view came with 6q-4), and it broke this slice's rule that a panel's key works wherever the keyboard is. Fixed in `3bdea3e8`: a press with Ctrl, Alt or the command key, and the releases the app's key holds wait for, are copied to the app's document; plain keys stay the page's, and what the app uses the page doesn't get. Failing first: `frameKeys.test.ts`.
3. **The app didn't know the keyboard was inside a rendered HTML file.** Found in run 2, once the keys arrived: no `focusin` leaves a frame, so the window still held Files as the panel with the keyboard, and Ctrl+Tab from `page.html` in Browser stepped Files' tabs. Fixed in `07cf09e9`: the frame's window passes its focus and blur on as `focusin` and `focusout` from the frame's element. Failing first: `frameFocus.test.ts`. Seen after a reload: Ctrl+Tab from the file stepped Browser's tabs.

## Observations (not fixed)

1. During a stack motion the page's box trails the layout the webview has computed by one to two frames (up to 25 px in the per-frame record). The captures show the painted frame and the page in step, so nothing of the page is seen over Files. If it ever shows, the fix is to place the page ahead on a row that is shrinking, or the plan's fallback of hiding it for the motion.
2. The line "Opened … in Browser." can be lost: the announcer says one message per 1.5 s, the latest wins, and the session's own line arrives when the shell command that ran `marshell open` ends. Older than this slice.
3. With the app's window in the background, a web page keeps native focus after the keyboard moves on (WebView2's focus events don't arrive), which makes Ctrl+Tab and the ring act for Browser. Known since the 2026-11-13 Ctrl+Tab rollover check, finding 2; the rows above were taken with no page holding it.
4. A session that ended has no terminal to take the keyboard: in run 2 (every session "Ended last time") the ring's terminal stop announced "Selected session 3, PowerShell 7 3" and the keyboard stayed where it was. Not compared with `main`.
5. A blank tab's toolbar shows "Stop" where "Reload" would be expected.
6. The finder behind "Open file…" listed only `server.mjs` in a folder of 39 files. Not looked into.
