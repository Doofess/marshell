## Findings

1. **A session's switch line was said again after a notice when the session's status flipped.** `SessionAnnouncer` handed `nextAnnouncement`'s text to the announcer on every render. So when a working→idle flip rendered the row again after a "Pasted …" notice, "Session 4, codex-lc" came back and covered the notice. Fixed in 9c6d2eac: `announcementStep` says nothing when the announcement is the one already said. Tests: "announcementStep: what the announcer says when the focused row renders again" (3 cases, failing first).
2. **A comment whose lines moved kept its old line numbers, and the keyboard jumped after the shift.** `place` found the rows again 5 lines down, but the item label, the draft saved from the box and the pasted citation still said line 12. A row's key held its index, so focus slid to another line. Fixed in e57b236f: `Placement` carries the lines' current `start` and `end`, which `renumbered` applies to the label, the saved draft and the citation. A row's key is now its content hash and how many identical rows come before it. `focusIndex` keeps the last index when a key goes. Tests in `comments.test.ts` ("cites the lines a moved comment's rows are on now") and `model.test.ts` (row keys, `focusIndex`, the moved label), all failing first.
3. **With a 6,002-row file open, every poll drew every row again.** A `same` reply still set a new state object, and no row was memoized, so each 2-second poll cost a 220 ms frame. Fixed in 44f6f5f8. `changesState` keeps the state object when nothing changed, the unused `busy` state is gone, and each row is a memoized component whose handlers keep their identity. Test: `changesState` in `useChanges.test.ts`, failing first.
4. **Syntax colours stayed on in forced colours.** The diff rows set `forced-color-adjust: none` to keep their signs and fills under the system's colours, and their token spans inherit it, so the theme's token colours showed on the system's Canvas. Fixed in db2e6a86: the panel sets every `--code-token-*` back to `initial` in forced colours, as `Preview.css` does. Test: `ChangesPanel.css.test.ts`, which reads the variable list from `tokens.css`, failing first.
5. **A new file past the 200 cap gets no mark in the tree.** In row 9, `src/extra.ts` came after `gen/f001` to `f300` in the sorted list, so it was neither in Changes nor marked "A" in the tree; the strip's "And 102 more new files aren't shown." is the only sign of it. This follows the plan's cap (`MAX_NEW_FILES`, 200, in the 6r-3 plan's Global Constraints). Not fixed.
6. **`git diff` opens a submodule's repository even with `--ignore-submodules=all`.** The trace has a `def_repo` for `repo/sub` in each diff run (83 in row 2). Nothing in it runs: git started no child process, and the marker stayed empty. Task 4's test `a_submodule_config_runs_nothing` pins the same thing for a submodule whose own config sets a filter. I first took this for no defect. The final review showed otherwise: before it reads `--ignore-submodules`, git resolves each gitlink's ref (`ce_compare_gitlink`, and `check_removed` for a tracked file that is now a folder), so it follows a submodule's `.git` file, `commondir` and refs wherever they lead, a network path included. Fixed in 65edb72e, with c688663e for the parsing: `gitbox::worktree::reach` looks at every folder on the way to a tracked path before git is given the work tree, and refuses the repository when one leads to a network or device path (`a_submodule_whose_git_file_names_a_network_folder_is_refused` and twelve more, and `a_submodule_whose_git_file_names_a_network_path_is_refused` at the Changes level, each failing first).
7. **Method: never run git in the trap repo yourself.** Before row 2, my own `git -C …\repo ls-files`, run to list the tracked files, ran the trap's fsmonitor and wrote "fsmonitor" to the marker. The marker was emptied before Marshell was pointed at the repo, and it stayed empty through row 2.
8. **Showing Changes with its key left the keyboard where it was.** Row 3 recorded it as the rule, but Browser and Files take the keyboard when their key shows them. The panel draws nothing before its first reply, `focusPane` waited only 3 frames for it, and most of its empty states have no button to take the focus. Found by the pre-merge review, not by the check. Fixed: `focusPane` waits up to about 3 s while the panel is blank and gives up if the keyboard went elsewhere meanwhile, and an empty state with no button lets its title take the focus (`focusPane in Changes` and `with no action its title can take the focus`, each failing first). Not checked again in the real app.
