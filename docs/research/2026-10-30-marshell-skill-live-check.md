## Findings

1. **Codex 0.164 reads `~/.agents/skills` from the real profile, not from `USERPROFILE`.** With `USERPROFILE` pointed at the scratch home, Codex's `/skills` listed the real `setup-check` skill from the real `~/.agents/skills` and not the scratch `marshell`, so Codex resolves the home folder through Windows itself. In normal use both are the same folder, so Marshell's path is the one Codex reads; a live check can't show it without writing to the real profile. The file's format was checked instead: a copy in the scratch project's `.agents\skills\marshell` was listed by Codex with its description, then removed.
2. **Focus after a plan or an Apply.** After Settings' plan, focus lands on the "Agents" heading; after Apply, on the page body. The existing hooks panel behaves the same way, so this is the pattern, not a regression. Known limit.
3. **A stale row after a conflict.** After the 409 and Reload, the row still read "Installed in …" while the file was edited; the diff it showed was right. Reopening Settings fixes it. Minor.
4. **Settings doesn't re-read the setup while it is open**, so a file changed by hand shows only after reopening Settings. Pre-existing.
5. **The consent card's undo sentence doesn't mention the skill.** It still reads "To undo: Marshell removes the hook entries … it added; the rest of the file stays as it is." with the skill switch on.
6. **Uninstall's summary doesn't say whose skill.** It printed "Marshell takes out the skill it installed." once per skill, without the agent's name.
7. **Claude's own command check, outside this slice.** Before asking permission, Claude Code said "Command contains malformed syntax that cannot be parsed: pwsh exited with code 1: The command line is too long." about the one-line command above. The command then ran fine. It looks like Claude's parser check failing in the session's environment, not anything in the skill.
8. **The dev window closed during run 1** (15:51:07, "Failed to unregister class Chrome_WidgetWin_0", then `ELIFECYCLE -1`); likely the window was closed. Run 2 started fresh. The favicon 404 in the console is benign.
