- Date: 2026-11-20. Run 1 from 21:33 to 21:47 local time, run 2 from 22:01 to 22:15.
- Build: `phase-6n2` under `pnpm tauri dev` on Windows 11 Pro (10.0.26300). Run 1 was at `ffd86caf`, before the final review's fix pass. Run 2 was at `df5e7f05`, after it.

Run 2 had `COPILOT_HOME=C:\copilot-6n2-scratch` (outside the profile; the PC has one drive) and a made-up `GH_TOKEN`. Onboarding set up Copilot CLI only; the other four cards were skipped.
- Copilot CLI: the PC's own 1.0.106, with the check's fake model (`-CopilotFake`), so no sign-in was used. `live-check.ps1` got a `-CopilotHome` option for run 2.
- WSL: the user's own Ubuntu, with their OK, because "Set up in Ubuntu" writes the distro user's real `~/.copilot`, which did not exist before. Node v22.23.5 (sha256 checked) and `@github/copilot@1.0.106` went into `/tmp/copilot-6n2-lc`, with a second fake model inside the distro on port 48763. Marshell skips every `/mnt/` entry of the distro's PATH, so a wrapper script went into `~/.local/bin/copilot` (neither `~/.local` nor `~/.local/bin` existed). The wrapper and both folders were removed when the check ended.
- End state: `live-check.ps1 stop` ended all 23 recorded processes of run 1 and all 28 of run 2, and both fake models. The real `~/.claude/settings.json` still had its 2026-11-20 12:51:33 time, and the real `~/.copilot` still had no `settings.json` and its `config.json` of 2026-09-21. In Ubuntu, `~/.copilot` holds what the check and Copilot wrote, with the hooks off.
- Data: a made-up `config.json` naming `octo-check` as the last account; nothing else seeded. Copies of the settings files and the WSL session's log are in the scratch `evidence\` folders.
- How it was driven: CDP evaluations, clicks and keys in the webview, emulated forced colours (not a real high-contrast theme), and about ten screenshots to read Copilot's terminal UI. `wsl.exe -e bash <script>` for the distro side. No desktop input.

## Findings

1. **With "Copy conversations run outside Marshell" off, a Codex, Qwen Code or Copilot CLI conversation run inside Marshell has no transcript.** Seen for Copilot in run 2: the session was listed as "Untitled conversation · 0 turns" with only its sidecar, and its copy appeared seconds after the switch went back on. For these three CLIs the history recorder never asks for a copy (`note_event`, `ends_turn = !codex && …`), so the importer is their only copier, and the switch stops it. The same code path serves Codex and Qwen Code, so this predates the slice. Not fixed: it is a change to the importer for three CLIs.
2. **A Copilot conversation run in a WSL tab is listed without its turns.** The tab links to the session (hooks and status line), but the importer reads no distro and the recorder makes no copy for Copilot. Codex and Qwen Code do the same in a WSL tab (the 6j1 live check, and 6m decision 10). Not fixed; same root as finding 1.
3. **The final review found four things worth fixing, fixed in `df5e7f05`.** A moved CLI home was checked as written, so a drive letter mapped to a share opened the share (failing first: `a_home_that_really_is_on_a_share_adds_nothing`). The held end of a Copilot session was compared with the history index only, so with History off, or the index slower than the hold, `/clear` could still read Ended (failing first: `a_clear_never_shows_ended_with_history_off`). The announcement after a Copilot sign-in named the CLI twice and left out the last account (failing first: `signInResult`, two tests). Run 2 saw the second and third fixed in the app.
4. **Copilot looks for skills from the working folder up to the home.** It lists the `.agents/skills` and `.claude/skills` of every folder on the way as `inherited`, and a name is listed once: an inherited `.agents` copy wins over `~/.copilot/skills`. In a live check, a project folder under the real profile makes Copilot read the real home's skills, so the check's Copilot sessions ran in a folder under the scratch `USERPROFILE`. The launcher's default folder is the real profile whatever `USERPROFILE` says, and one Copilot tab of run 2 started there by mistake (the Folder field's "Use" row was not picked). It was closed within a minute, and Copilot's home was the scratch one.
5. **`/model` changes the session only; `/config model` writes `settings.json` and keeps the other keys.** So Review needs no "Copilot is running" warning (decision 8).
6. **`copilot login` under `COPILOT_OFFLINE=true` prints "Login is not available in offline mode." and exits with code 1.** The sign-in tab is the check's own; a real sign-in was not tried.
7. **The shape of `lastLoggedInUser` is still unverified against a real sign-in.** The PC's real `config.json` holds only `firstLaunchAt`. The account line was checked against a hand-made file built from Copilot's source.
8. **After `/clear`, History lists the new session as "Untitled conversation · 0 turns" until its first prompt.** Copilot creates the session's folder at once and its log only with the first prompt. Expected.
9. **Hooks off does not delete a `settings.json` that set-up created, and a one-line file comes back over several lines.** In Ubuntu, where there was no file, Hooks off left `{}` and an empty `hooks` folder. In the moved home, the check's one-line seed (`{"autoUpdate": false, "taskbarPresence": false}`) came back over four lines with the same keys. Every later set-up and turn-off cycle is byte-equal. The diff at Review shows each change. Expected, not a bug.
10. **Once, the launcher opened with focus on the page body after Ctrl+Shift+W closed the last tab,** and Escape did nothing until a button inside it was focused (run 1, with Settings open shortly before). In run 2 the same keys put focus on "Agent: Claude". Not reproduced, not fixed.
11. **The five "Set up in Ubuntu" and "Remove from Ubuntu" buttons in the Agents section have the same name.** Each sits in its CLI's block, and none names the CLI. This predates the slice (6j1). Not fixed.
12. **The restart bar of a sign-in tab read "Resume runs custom in C:\Users\Home Office".** Not looked into.
