## Findings

1. **Qwen runs `echo` without asking.** Qwen 0.26.5 treats a read-only command as safe in its default mode, so the plan's `RUN echo marshell` never sends a PermissionRequest. The check used `mkdir` for every card. Not a bug; a later live check should use a command that writes.
2. **The mode chip's label said Qwen's mode wasn't tracked.** The chip's text followed Qwen's reported mode ("Full auto" after Tab inside Qwen), but its label and title read "Started in Full auto. A change made inside the CLI isn't shown yet.", because `modeTitle` gave the tracked wording only to Claude Code. Fixed in d8be293: Qwen's chip reads "Mode: Full auto, as Qwen Code last reported." Test `says a Qwen Code session's mode is the one it last reported, since its hooks carry the mode too` went RED → GREEN.
3. **The card's note was set in the monospace path font.** It borrowed `approve-card__cwd`, the folder line's class. Fixed in d8be293: the note has its own rule in the card's text font (`--text-12`, `--text-2`), and the lane still clamps it at three lines. The tests `a Qwen card has Allow and Deny and no Always allow` (markup) and `styles the note itself, in the card's text font rather than the folder line's monospace` (stylesheet) went RED → GREEN.
4. **The restart bar names `qwen --continue`, while the core runs `qwen --resume <id>`.** The same shared copy gap the Antigravity check recorded (slice 6d, finding 3) for every agent. Not fixed.
5. **Qwen rewrites its own `settings.json`.** On its first run it adds `"$version": 4` and re-indents the file, and when Auto mode is first chosen it adds `ui.autoModeAcknowledged`. So the plan's "byte-equal to before the setup" can't hold once Qwen has run, whatever Marshell does. Marshell's own round trip is byte-equal, and Marshell kept seeing its install as on after Qwen's rewrite. Not a Marshell bug.
6. **Full auto still asks.** Qwen's `auto` mode sent a PermissionRequest for `mkdir`, so a Full auto Qwen tab still raises cards. Only `yolo` (Bypass) skips them.
7. **`statusline-chain.json` stays after Hooks off.** It still holds the person's line, which is back in `settings.json`. Not checked against Antigravity's removal; left as an observation.
8. **One console error at the first tab's start.** `WebSocket connection to 'ws://127.0.0.1:65073/v1/pty/t1483ff7042e9' failed: … 404`, once, as session 1 started. The terminal connected and worked. Not investigated.
