## Findings

1. **Detailed logs adds nothing to the log (not fixed).** `log::set_detailed` reloads the filter and `/v1/diagnostics/logging` reports it, but no code in Marshell's crates emits a debug or trace line, so turning it on writes no new line. Which events to log at debug is a product call with a privacy side (a debug line near a hook, a prompt or a session's input must not carry its body, and the export promises it holds none), so it is left. The reload is covered only by the unit tests in `diagnostics/log.rs`, not shown live.
2. **After a keyboard Prepare or Save…, Escape did not close the dialog (fixed, cf53fa0).** Both buttons set `disabled` while busy, and a disabled button that has focus drops it to the page. Escape and Tab are handled on the dialog, so with focus on `<body>` Esc did nothing and the dialog could not be closed from the keyboard. The two buttons are now `aria-disabled` while busy and their handlers ignore a press, as the approval card's buttons already do. The test (`keeps focus on a button that is busy`) failed first. Live afterwards: focus stays on Prepare again, or on Save… through the native dialog and its Cancel, and Esc closes the dialog and returns focus to the terminal.
3. **The 8.3 short form of the profile folder is not redacted (not fixed).** The `~` rule knows the profile folder only in its long spelling (`%USERPROFILE%`), so `C:\Users\JANEDO~1\AppData\Local\Temp\marshell-3e2 project\…` went into `agents/claude.json` as it was, which gives away the first six letters of the user name. On Windows `%TEMP%` is commonly in this form (it was on this machine, whose user name has a space), so a Temp path in a log line, a crash report or a path Marshell shows can carry it. A fix needs the short name of the profile folder (`GetShortPathNameW`) or a pattern for `Users\<up to 6>~<digit>`, so it is left. The Marshell home in this form got `<marshell-home>` and was not leaked.

### Minor, not fixed

- In forced colours the switch's focus ring differs from its resting outline only in width (1px to 2px, both `CanvasText`), while this dialog's buttons get a 2px `Highlight` ring. The switch is the shared `Switch` component, so it was left.
- The tab trap reaches `<body>` only through a disabled control, which finding 2 removed for this dialog. Other dialogs (Agents' Turn off, `disabled={busy}`) use the same pattern and probably have the same fault.
- The native Save dialog opens in Documents, which is the OS default, since the app passes no folder.
- The first count of `/v1/perf` request events while the panel was open was 11 in 6 s, with the first few back to back. A second count by method gave 5 `GET` and 1 `OPTIONS` in 5 s, so the steady rate is one a second, but the cause of the burst at open was not looked at.
