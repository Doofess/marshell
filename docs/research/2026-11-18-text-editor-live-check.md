## Findings

1. **The navigation layer read the editor as nothing focused.** `focusKindOf` knew inputs and text areas only, so in the editor a bare Esc went to the main area, the Tab that should leave selected the terminal, and Ctrl+Shift+arrows moved between panes. It now reads an editable element as a text box. When the side pane takes the keyboard it goes to the editor of a text tab, not to the tab's body, so Ctrl+Shift+Tab comes back to the cursor. Fixed in `ecf9e343`; `useNavigation.test.ts` "is a text box in the editor" and `focusPane.test.ts` "is the editor of a text tab that shows one" failed first.
2. **Esc with text selected did not arm the Tab that leaves.** CodeMirror arms it only when no binding handled the Esc, and with a selection one does. A binding of ours arms it on every Esc. Fixed in `ecf9e343`; `setup.test.ts` `esc_always_makes_the_next_tab_leave` failed first. The go-to-line box's button had no copy in the plan and reads "Go".
3. **Undo of a save put the old text in the editor.** PLAN §9 decision 8 says the file goes back and the editor keeps the person's text. After an undo the text now stays and the tab is unsaved again, with a draft. Fixed in `339ed1eb`; `editorDoc.test.ts` `step_the_disk_after_an_unsave_leaves_the_text_which_is_unsaved_again` failed first.
4. **Undo, Keep mine and Take disk took the keyboard with them.** Each button goes away when pressed, and focus fell to the page. The keyboard now goes to the editor first, or to the tab's body in Rendered view. Fixed in `339ed1eb`; `TextTab.test.tsx` `keyboardTo` failed first.
5. **Every text file opened logged a 404 in the webview console, and Ctrl+S under the bar was silent.** The editor asks the core for a draft of each file it opens, and no draft was a 404, which a webview logs as an error. The core now answers 204 (`effe979a`; `drafts_api.rs` `get_of_no_draft_is_a_204` and `editorApi.test.ts` "getDraft is null on a 204" failed first). Ctrl+S while the bar is up did nothing and said nothing; it now says the file wasn't saved (`c98bb454`; `editorDoc.test.ts` `step_save_while_a_conflict_is_up_writes_nothing_and_says_why` failed first).
6. **After Save in the close question the keyboard fell to nothing.** The close that follows a save is drawn later than the frame focus is asked in, so the closing tab's editor took the focus and went. Focus now waits until that tab is gone. Fixed in `0d4c414f`; `focusPane.test.ts` "is nothing while a tab that is closing is still drawn" failed first.
7. **A shebang script started with word wrap on.** Its name gives no type, so it counted as plain text though it was coloured as code. Fixed in `d3f24856`; `TextTab.test.tsx` `wrapAtStart` failed first.
8. **Once a browser tab exists, Tab from the window's last control leaves the document for one press.** With a page's webview in the window, Tab from the editor (after Esc) or from the last link of a rendered Markdown file left `document.hasFocus()` false, and the next Tab came back. Before a browser tab existed the same Tab went to the window's first control. It is older than this slice. Not fixed.
9. **After a tab closes, the keyboard can land on the next tab's body.** When the next tab's file has not loaded within three frames, its body takes the focus, not its editor. Not fixed.
10. **A link followed from a tab with unsaved edits asks nothing.** The draft is kept and Back brings the edits back, but while the tab shows the other file no tab carries the dot. Not fixed.
11. **The footer's hint is the same in a read-only editor,** where Tab alone leaves. Not fixed.
12. **Text put in through CDP's `Input.insertText` is slow.** 6,000 lines took 64 s that way, through the editable element itself; the same text as a paste event took 3 ms. Typing, a paste and a drop don't take that path. Not fixed.
