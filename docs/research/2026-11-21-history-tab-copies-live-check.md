- Date: 2026-11-21, about 01:50 to 02:31 local time (UTC+2). Times below are UTC.
- Build: `phase-6s` (at `d344b8e3`) under `pnpm tauri dev` on Windows 11 Pro (10.0.26300).
- Home: scratch `MARSHELL_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `USERPROFILE` and `MARSHELL_CLAUDE_SETTINGS`, with CDP on port 9333. Three scratch folders: `lc-6s-1` (Windows tabs and the start-up pass), `C:\lc-6s-wide` (the guard, started with `-CodexHomeWide`) and `lc-6s-2` (WSL tabs). - WSL: the user's Ubuntu. Node v22.23.5 and both CLIs went under `/tmp/lc-6s` (a tmpfs), with a fake model on port 48763 in the distro. With the user's OK, two wrapper scripts were put in `~/.local/bin` (neither `~/.local` nor `~/.local/bin` existed) and all four were removed at the end. - How it was driven: CDP evaluations in the webview (authenticated `fetch` calls to the core from inside the page, so the token never left it), text typed through `POST /v1/sessions/<tab>/input`, Enter and Escape as synthetic key events on the tab's terminal, emulated forced colours (not a real high-contrast theme), five screenshots. Archives were decompressed with Node's `zlib.zstdDecompressSync` and compared with the source files. No desktop input.

## Findings

1. **Under a wide `CODEX_HOME`, the same sentence is shown for other CLIs' files that lie inside it.** In the `C:\lc-6s-wide` run, Claude Code's `proj\.claude\settings.local.json`, Antigravity's `home\.gemini\…` and Qwen Code's `home\.qwen\settings.json` were refused with "CODEX_HOME names C:\lc-6s-wide, a folder that holds your user profile." Here it comes from the scratch layout: the scratch `USERPROFILE` is not the profile the core resolves, so those files are outside every allowed folder and inside the wide one. In real use it needs a file outside the user's home and projects yet inside the wide folder (for example `CODEX_HOME=C:\`). The refusal itself is right; only the named reason is another CLI's variable. Not fixed; a known limit.
2. **Listing projects starts a stopped WSL distro.** With a project folder under `\\wsl.localhost\Ubuntu\…` in `projects.json`, every page load started Ubuntu for about 15 s. Called one at a time 24 s apart, `GET /v1/projects` and `GET /v1/agents/<cli>/setup` each started it; `/v1/agents`, `/v1/agents/catalog` and `/v1/layout` did not. `projects::list` checks `Path::exists()` on every recorded folder, and the config guard calls it for each request. The same code is on `main` (`projects.rs:237`, `guard.rs:60`), so this is older than the slice. Not fixed here: the guard's folder list is outside the slice's decisions. Issue #158.
3. **An open History row keeps its old turn count.** With History open during a Qwen turn the row stayed at "3 turns" while the API said 4; reopening History showed "4 turns". Known and left by the slice's decision 9; issue #157 holds the live refresh.
4. **Whether Codex sends `Stop` as well as `Interrupt` on Esc could not be told.** Marshell logs no hook events. One copy followed the interrupt either way, and the row's time moved once.
5. **The first render can take a minute or two.** In two of the starts the page's root stayed empty for 70 to 120 s and then rendered, with nothing in the console but a favicon 404. The window was hidden behind others; not looked into.
6. **Codex's row read "Status limited" in Manual mode** although its hooks were trusted and its copies arrived. Not looked into.
