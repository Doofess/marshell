# herdr-app: what is worth taking

- Date: 2026-11-10.
- What was read: `herdrdev/herdr-app` (the desktop app, v0.1.14), parts of `herdrdev/herdr-core` (its runtime, v0.1.19) and the integration, detection and resume code of `herdrdev/herdr` (v1, a TUI multiplexer), from clones in a scratch folder, plus eight issue bodies.
- How: a read-only study by a Sonnet agent. Nothing was built or run, so every behaviour here is read from code or prose and none was seen on Windows. Section 7 lists what was not verified.
- Status: a study. No slice is planned from it yet.

Paths are relative to a repo: "app:" is `herdr-app`, "core:" is `herdr-core`, "v1:" is `herdr`. **[README]**, **[docs]** and **[issue #n]** mark claims taken from prose and not from code that was read. Line numbers are from the clone of 2026-11-10 and may drift.

## 1. What it is

Herdr 2 is a native desktop app for terminals and coding agents. Work lives in spaces (one repo or machine each). Each space has tabs, and each tab is split into panes. A sidebar lists agents by state: working, blocked, done, idle. Closing the window leaves terminals running, because a separate program, `herdr-core` (`hc`), owns the ptys. Spaces can also run on SSH machines. The sidebar, tab bar, menus, dialogs and the Files and Changes panels are JavaScript "mods" drawn by the GPU. It is three weeks old and moving fast. It is not Tauri, not a webview, and has no browser, PDF or editor preview.

## 2. How it works

**Two programs.** The app draws. The core (`hc`) runs terminals and draws nothing. The `hc` CLI and the app are both clients of the core. `hc schema` prints an OpenRPC description, and `hc connect` tunnels over stdin/stdout for SSH.

**Holders.** Small holder processes own every pty, always read output, and keep about 1 MB of tail per terminal. A crashed core is restarted, and updates leave programs running (`core:crates/herdr-core/src/holder.rs`, `holder_proto.rs`, `kept.rs`, `sweep.rs`, `runtime.rs`).

**Windows.** `core:crates/herdr-core/src/platform/windows.rs` uses overlapped named pipes, with an ACL for the current account and SYSTEM. ConPTY comes from a bundled `conpty.dll` plus `OpenConsole.exe`, and job objects handle cleanup. There is no per-client password.

**App state.**

- Spaces, tabs and the split tree are stored per machine in a core document named `herdr-app`, read and written with `doc.get` and `doc.set` under a version compare-and-swap. On conflict the app rereads and the newest accepted document wins, with no merge (`app:src/mirror_sync.rs`, `app:src/mirror.rs`).
- Per-screen state (focus, zoom, settled tabs, seen state) is in `view.json`.
- Files under `~/.config/herdr-app`: `layouts/`, `keys.json`, `settings.json`, `mods/`, `shared.json`, `programs.json`.
- The app has a control socket. `herdr-app ls | status | commands | do <cmd> | check <mod> | shot [png] | feedback` drives the live window (`app:src/SKILL.md`).

**Status (v2).** The core stores only what a program reports through one escape sequence, OSC 7501, the "Program Status Protocol": `state=idle|working|done|blocked|error`, `kind` (permission, question, auth), `progress`, `app`, `title`/`msg`, an `id` for child records, and `clear`. The rule (`core:AGENTS.md`): "Status comes only from OSC 7501. No screen detection, no agent registry, no vendor-specific logic." An agent that doesn't emit it gets no status. Claude Code, Codex and Antigravity are said to emit it **[issue #785, quoting a third-party tracker]**; Cursor does not.

**Orchestration.** `hc run --bg --name`, `hc send`, `hc wait --children`, `hc read`, `hc interrupt`, `hc keys`, `hc events`. Children end with their parent unless `--outlive-parent`. Templates are Markdown files (`core:docs/templates.md`).

**Agent guide.** `app:defaults/AGENTS.md` (1,057 lines) is rewritten at every start. It is the guide for users' agents, and `cargo test` checks that it names every command and settings key **[`app:AGENTS.md`]**.

**Updates.** `app:src/update.rs` checks `releases.herdr.dev/app/latest.json` hourly, verifies SHA-256, unpacks beside the install and swaps on quit, restart or after a crash. `docs/security.md` says the checksum is not an independent signature. Telemetry is on by default (a daily report, opt-out in Settings or by `DO_NOT_TRACK=1`).

## 3. Ideas worth taking, best first

"Has / part / lacks" compares with Marshell as the agent was told of it; check each against the code before planning.

1. **"Done" means finished while you were not looking, kept as a turn counter.** The core's `turn` counter rises each time the root record leaves `working`; child records don't count (`core:crates/herdr-core/src/status.rs`). The app shows "done" while `turn > seen_turn`, else "idle" (`app:src/model.rs`, `Agent`, `status()`). Blocked or error always alerts; finishing alerts only if you were not looking; sub-agents never alert. Priority is blocked, done, working, idle, rolled up per tab and space. "Looking" means the window is in front and the agent is drawn. Mark-unread writes `turn-1` (`app:docs/labels.md`). Marshell: part. Size: small to medium.
2. **Split panes** (section 4). The new pane takes half of its target's share and a removed pane's share goes back to its neighbour; a program is spawned at the size its pane will have, computed from the future tree; hidden tabs are fitted once the window's geometry has been stable for two ticks. Marshell: removed its own split view in slice 6q-1. Size: medium to large.
3. **Lessons for hook-fed status.** v1 used hooks plus screen manifests, then partly retreated (`v1:CHANGELOG.md`): Copilot, Devin and Droid state stays screen-detected "because hooks do not provide complete lifecycle coverage"; Codex turn hooks were dropped after a "clamping Interrupt hook timeout" warning (0.9.5); a sub-agent's hook events must not make its parent look idle; stale or out-of-order reports are rejected with sequence numbers; hook state clears when the process exits; Qwen state comes from OSC title glyphs (`v1:src/detect/manifests/qwen.toml`). Detection rules are TOML data with regions, priorities and a version. Marshell: has hook status; stale-report guards and a clear-on-exit rule are worth checking. Size: medium; a second signal is large and touches "no guessed status values".
4. **Resume a past agent session from a stored id, one command per CLI** (`v1:src/agent_resume.rs`): `claude --resume <id>`, `codex resume <id>`, `copilot --resume=<id>`, `qwen --resume <id>`, `agy --conversation <id>`, and others. It validates a bare command name, no control characters, no apostrophes, at most 64 args and 8,192 bytes. Size: medium.
5. **Terminals that outlive the window and updates,** a holder process per pty. A lost terminal becomes a fresh shell in its last folder; the old command is never rerun (`core:kept.rs`). Size: large.
6. **A draft-aware input gate** (`core:crates/herdr-core/src/input.rs`, `Gate`). One queue per terminal; it parses CSI-u, bracketed paste and backspace to track the person's unfinished draft. An agent's sends and notes wait until the person has been quiet 3 s, or up to 60 s if there is a draft. Size: medium.
7. **Safe edits to files the app also ships** (`app:defaults/AGENTS.md`). A shipped layout or mod is replaced at start, and an edited one is moved to `<name>-edited`. A broken save keeps the last good version and writes `<name>.error`. One key chord resets layout and keys. A corrupt `shared.json` is kept as `.corrupt-<time>`. Marshell: part.
8. **Worktree removal that checks what you would lose** (`app:defaults/mods/worktree/main.js`). It closes the space first (a shell in the folder keeps it busy on Windows), warns about uncommitted changes and unpushed submodule commits, and checks again at confirm time: "It changed since this opened. Enter again removes it anyway." Marshell: has worktree tasks; the submodule check and the re-ask are small.
9. **A Changes panel that can't feed its own folder watcher** (`app:defaults/mods/changes/main.js`). Git is read with `--no-optional-locks -c core.fsmonitor=false -c diff.autoRefreshIndex=false`, with limits of 1,000 files, 1,500 diff lines and 4,000 characters a line. Size: small.
10. **Attention-first agent list** (`app:defaults/mods/agents/main.js`). Sorted by priority (Needs you, Done, Working, Idle) or grouped by space; pin, fold, a duration per agent, sub-agents under their parent; `tab.settle` puts a tab away until an agent needs you. Marshell: part. Size: small.
11. **One command list for keys, palette, menus, CLI and agents.** `herdr-app commands` lists them, `keys.json` binds `"ctrl-shift-o": "pane.split:right"`, `herdr-app do <cmd> '{json}'` runs one, and an unknown argument fails and lists the valid names (`app:docs/commands.md`). Marshell: has the palette and keymap; a CLI over the same list is missing. Size: medium.
12. **An agent-readable guide and the app's own screenshot.** `herdr-app shot` saves the app's last frame even when covered; `check <mod>` renders once and exits nonzero with the error. Size: small to medium.
13. **Peek, and sub-agents without panes.** Ctrl+click an address such as `t7` in terminal text opens that terminal in an overlay. A parent gets a typed note when a child blocks (`core:notes.rs`). Size: medium; sub-agents large.
14. **The update flow and release notes.** Download beside the running app, swap on quit; `CHANGELOG.md` markers drive a What's New window. Size: small.
15. **The first task goes in with the launch.** `tab.new --task` sends the first message after the first status report (`core:docs/templates.md`). Size: small.
16. **Idle cost as a feature.** Idle windows stop waking every vsync; `app:scripts/bench.py` runs fixed workloads with draw counters.
17. **Small terminal details.** Find per terminal with its own query; OSC 52 writes up to 1 MiB and never reads; a file drop pastes quoted paths (`app:CHANGELOG.md` 0.1.5 to 0.1.14).

## 4. Split panes

### 4.1 Data model

- **Tab.** `Tab` in `app:src/model.rs` (about lines 11 to 30) has `root: Node`, `focused`, `before` (focus history, 32 at most), `zoomed`, `settled`, and `rest` (unknown fields from newer builds, written back). `shown()` returns the zoomed pane or the root.
- **Node.** The tree is `Node` in `app:src/layout.rs` (line 316). `Kind` is Block, Row, Column or Stack. Each node has `min`, `max`, `hidden`, `gap`, `divider`, `resizable`, `movable` and `closable`.
- **Size.** `Size` is `Px{px}` or `Weight{weight}` (lines 80 to 85).
- **Ids.** A pane id is random 128-bit hex with a prefix. The terminal's address (`t7`) is the core's id, separate from the pane's.
- **Mod panes.** A mod can be a pane beside a terminal (`split_mod`, `app:src/window.rs` 2511).

### 4.2 Create

- **Commands.** `pane.split` takes `direction` "right" or "down" (`window.rs` about 3010; `app:docs/commands.md`). `terminal.open --place right|down` also splits.
- **Default keys** (`app:defaults/keys.json`). `ctrl-shift-o` splits right, `ctrl-shift-e` splits down, `ctrl-shift-x` closes, `ctrl-shift-z` zooms. `alt-h/j/k/l` and `alt-left/right` move focus. `alt-shift-h/j/k/l` swap panes.
- **Spawn order** (`window.rs`, `split()`, 2491 to 2509). Clone the tree, apply the split to the clone, compute the new pane's `initial_size`, spawn the terminal at that size, then update the model. The new pane inherits the target's folder and machine.
- **Tree edit** (`Node::split`, `layout.rs` 581 to 612). If the parent already runs along the axis, the new node goes in after the target and halves its weight; a Px target keeps its px. Otherwise the target is wrapped in a new container that keeps the slot's size.

### 4.3 Close

- `pane.close` (`window.rs` about 3022) respects `closable`. The last pane closes the tab. Otherwise the pane leaves the model and then the terminal is killed.
- **Tree edit** (`layout.rs` 568, 660 to 713). The removed share goes to the previous neighbour, else the next. A row or column left with one child gives way to it. Empty containers vanish.
- **Focus** (`model.rs` 358 to 380) returns to the most recent surviving pane in the history, else the first.
- A pane whose program exits closes only after the core confirms it; a failed lookup is not evidence of an exit.

### 4.4 Resize and rearrange

- **Mouse only.** The handle is 6 px (`window.rs:33`); `drag_to()` is at 4281 to 4335. It measures the two neighbours, needs a total above 48 px, clamps to [24, total − 24] and honours `min` and `max`. A Px sibling gets the px; otherwise both are rewritten as weights with their sum kept. There is no snapping to cells.
- **Missing, by open request:** a pane-resize command (#117), equalize (#540), rotate (#541), move to edge (#179), preset arrangements (#551).
- **Rearrange.** `pane.swap` by direction or target. A pane drag (`app:src/window/pane_drag.rs`): a grip appears on a hover at the top edge; the outer quarter of the target places the pane beside it, the middle swaps.
- **Zoom.** `pane.zoom` toggles only when the tab has more than one pane. While zoomed, a focus move takes the zoom with it.

### 4.5 Focus

- `pane.go` (3070) ends in the free function `nearest()` (4528). It is geometric, over the bounds of the drawn blocks: it needs a gap above −2 px and some overlap, and prefers the smallest gap, then the most recently focused pane, then the largest overlap. A 1 px tolerance takes up subpixel noise (this closed #279, where returning to a split column landed on the bottom pane).
- **Gaps:** no directional move while zoomed (#386); no focus by number or cycle (#166); the focus ring stays while a mod has the keyboard (#362).

### 4.6 Sizing and redraw of each pane

1. **Grid size.** `app:src/terminal.rs`, `grid_size` (51 to 55): columns are floor((width − 2 × pad) / cell width), 2 at least; rows the same, 1 at least.
2. **Fit on paint.** The terminal view's prepaint calls `grid_size`, then `Grid::fit` (214 to 233), which does nothing when columns, rows and cell are unchanged; otherwise it resizes the local VT and sends the core a resize.
3. **Attach.** `TerminalView::attach` waits for the pane's layout before replay, for 100 ms at most.
4. **Core.** `core:crates/herdr-core/src/viewers.rs`, `apply_size` (about 328 to 352): the size of the viewer that typed most recently is the terminal's size.
5. **Predicting the size.** `app:src/window/pane_size.rs`: `pane_size` and `shares` work the grid out before drawing, modelling weights after fixed siblings, gaps, min/max, borders, header height, padding and zoom, so the size a program starts at matches the renderer's. `fit_hidden_tabs` resizes the terminals of hidden tabs once the window's geometry is unchanged across two ticks. Tests are in `src/window/pane_size_tests.rs`.
6. **Changelog.** "Programs start at the size of their pane" (0.1.13). "Tabs you're not looking at resize with the window" (0.1.13).
7. **Open problems,** all from issues: the hidden-tab fit is skipped while a mod covers the tab (#756); the UI thread drains the whole queued backlog and stalls for seconds (#748); a focused terminal redraws at about 30 fps (#794); a pane draws two parts of the log over each other after scrolling on Linux (#632).

### 4.7 Save and restore

- The whole `Node` tree with its weights is saved in the per-machine `herdr-app` document (`mirror.rs`, `Document::capture`), written as a compare-and-swap of the latest state, "one request per machine and no operation queue" (`mirror_sync.rs`). The last writer wins.
- Focus, zoom and settled state are per screen, in `view.json`.
- Terminals are kept by the core. After a core crash or a reboot a lost terminal gets a shell in its last folder; splits stay.
- Unknown fields from newer builds are written back through `rest`.

### 4.8 Admitted limits

- No keyboard resize, equalize, rotate, move-to-edge, focus-by-number or presets. No moves across tabs or spaces (#434, #775).
- A pane can shrink to 2 columns: there is no minimum in cells.
- Open performance and leak issues: #748, #794, #604 (most of a core with many terminals), #560, #751 (switching layouts leaks about 1.36 MB a round trip).

## 5. Things to avoid

- **Strict "only reported status".** It leaves holes: Cursor (#785), Hermes classed as a shell (#442), OpenCode stuck "running" after Ctrl+C (#767), agy idle after quitting (#773), idle while sub-agents work (#627). Hooks have the same class of holes (idea 3).
- **Two environment contracts for hook scripts** (#358, #537, #538, #488). Keep one set of variables, and have Doctor check that a hook can reach the host, not only that it is installed.
- **A GPU UI with no accessibility tree.** None was found in the files searched; #203 says macOS exposes no focused text element. Herdr is no model for Marshell's accessibility bar.
- **Unsandboxed mods** ("trusted JS", `docs/security.md`), with the leaks to show for it (#751).
- **Mouse-only, weight-only resize.** A keyboard-first product should not copy it.
- **A last-writer-wins layout document.** Two windows can lose a split.
- **Telemetry on by default and an update checked only by checksum.**

## 6. Other notes

- **Roadmap signals** (issue titles, none promised): pane commands (#117, #540, #541, #179, #551, #166, #434, #775), floating panes (#718), run something when a tab closes (#806), command-completion events (#749), keys by program (#745), several windows (#475), editing in Files (#610). A web-page mod was closed (#218).
- **Windows issues in the tracker** (titles only): clipboard replaced by a newline on a same-cell drag (#759), IME cursor (#700), text rougher than Windows Terminal (#694), messages to Codex stay unsubmitted (#491), Ctrl+J newline in Codex (#407), a URL opens File Explorer (#441), no AppUserModelID (#611), an elevated agent's `hc` starts an unreachable core (#623).
- **What herdr lacks that Marshell has:** no history or recordings view, no doctor, no browser, PDF or Markdown viewer among its mods, and no accessibility tree.

## 7. What was not verified

- Nothing was built or run. Windows behaviour is unobserved and the look is unseen.
- `window.rs`, `terminal.rs`, `vt.rs`, `mods.rs`, `update.rs` and most of the core's runtime were read only in part. Test suites were not read in full.
- Only issues #117, #540, #386, #279, #756, #748, #785 and #736 were read; every other issue is judged by its title. The code lines quoted from #748 and #756 come from the issues.
- That Claude Code, Codex and Antigravity emit OSC 7501 comes from #785, quoting a third-party page that was not opened. Whether Copilot or Qwen emit it is not shown anywhere that was read.
- Whether closing a pane asks first, and whether the context menu can split, were not traced.
- The vendored GPUI patches and the vendored trees' licences were not read.
- Counts (stars, forks, issues) are API values from 2026-11-10.
