## Findings

1. **Two files with one name got two buttons with the same label.** The clash in `pC` is about the user's `AGENTS.md` and the project's, and both buttons read "Open AGENTS.md", so neither a sighted person nor a screen reader could tell which file a press opens. Fixed: when an item's two buttons would share a label, each says its path as the detail shows it ("Open AGENTS.md" and "Open docs/AGENTS.md", or "Open ~/.codex/AGENTS.md"). Test `two_files_with_one_name_get_buttons_that_tell_them_apart` failed first.
2. **The import fix leaves the blank line that followed the import.** Removing line 3 of `pA/CLAUDE.md` left two blank lines between the heading and the next line. The fix removes the import's own line and nothing else, as decision 2 says. Not changed.
3. **Onboarding covers the window until every CLI has an answer.** The first "Open CLAUDE.md" with a session ran while onboarding was still on step 2, and focus went to its heading. With onboarding finished the press behaved as in row 8. Onboarding is not part of this slice. Not changed.
4. **Codex prints a second warning that this slice doesn't report.** With the default limit it also said "Combined user instructions use 32820 bytes, above the 32768-byte `project_doc_max_bytes` setting. … The limit applies only to project files." It is a notice about the total with the user-level file, and nothing is cut by it. Not changed.
