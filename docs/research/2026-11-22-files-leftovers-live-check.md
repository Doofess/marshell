## Findings

1. **In a Files panel under 480 px wide, the tree covers the path bar's "Collapse all folders" and "Show file tree" buttons.** The tree is drawn over the file at that width (6r-2 decision 6), and its filter box sits on top of the path bar's right end, so a click on either button lands in the filter box. A mouse can't hide the tree or collapse it from there. The Files menu has both commands, and the buttons still take keyboard focus. The empty file view's "Go to file…" button also shows a sliver at the tree's left edge. This comes from slice 6r-2, not this slice. Not fixed; filed as an issue.
2. **App shortcuts typed in the tree's filter box stay in the box.** Ctrl+Shift+P and Ctrl+Shift+T did nothing there. This is the rule in `src/features/tasks/reviewOpen.ts`: a search box keeps the app's shortcuts for itself, while the Address box and the editor give them up (the user's choice, 2026-11-10). Not a fault; recorded so a later check doesn't take it for one.
