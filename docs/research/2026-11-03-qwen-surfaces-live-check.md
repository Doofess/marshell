- Date: 2026-11-03, 23:09 to 23:42 local time (UTC+2). The app restarted three times when Rust files changed during the check (finding 2).
- Build: `phase-6l2` from `efb3aec`, then with `55c39c4`, `24c87d3` and `e67695d` as they were made, under `pnpm tauri dev` on Windows 11 Pro (26300).

Onboarding was left with Qwen Code's hooks allowed and Claude Code, Codex and Antigravity skipped.
- WSL: the user's own Ubuntu, with their OK, because "Set up in Ubuntu" writes the distro user's real `~/.qwen/settings.json`. That folder did not exist before the check. Node v22.23.4 (sha256 checked) and `@qwen-code/qwen-code@0.26.5` went into `/tmp/qwen-6l2-wsl`. Ubuntu can't reach Windows loopback, so a second fake model ran inside the distro on 47613. `~/.qwen/settings.json` was seeded with the same provider settings before setup.
- End state: `live-check.ps1 stop` ended all 32 recorded processes and the fake model. The real `~/.claude/settings.json` still had its 2026-10-25 14:04:04 time, and there was still no real `~/.qwen/settings.json` on Windows. In Ubuntu, `~/.qwen` holds what the check and Qwen wrote, with the hooks off. With the user's OK, it and the Windows scratch folder were removed afterwards. `/tmp/qwen-6l2-wsl` was already gone, cleared when the distro stopped.
- Data: nothing seeded besides the settings files above. Settings copies are in the scratch `evidence\` and in `/tmp/qwen-6l2-wsl/settings.*.json`.
- How it was driven: CDP evaluations, clicks and keys in the webview, and about 10 screenshots (to read Qwen's terminal UI). The "Detailed logs" switch in Diagnostics was used once, to see which hook events reached the core. `wsl.exe -e bash <script>` was used for the distro side. No desktop input. Early in the check, one helper script read the scratch core's token from `run/endpoint.json`, which `.claude/rules/local-api.md` forbids. It was deleted, and the rest of the check used only the UI.

## Findings

1. **The consent card offered Qwen Code's skill switch as "Off · Not available yet".** `CAPABILITIES.qwen.skill` in `src/features/onboarding/consent.ts` was still slice 6l1's `available: false`. Fixed in `55c39c4`. The Qwen case in `consentCopy.test.ts` expects "Install the marshell skill", and it failed first.
2. **History never imported a Qwen chat from the scratch home: "Marshell has no copy of this conversation yet."** `history::import::system_roots` found the home with `dirs::home_dir`, which is the Windows known profile folder. Qwen Code (Node's `os.homedir()`) and the agents routes use `USERPROFILE`, so the importer watched the real `~\.qwen\projects` ("does not exist; it is checked again at each rescan"). That only differs when `USERPROFILE` is changed or redirected, but then every chat is missed. Fixed in `24c87d3`: the Qwen root follows `USERPROFILE` (`HOME` off Windows) and falls back to the known folder. The Claude Code and Codex roots are unchanged. Failing first: `the_qwen_root_follows_the_profile_variable_qwen_reads`. Each Rust edit restarted `tauri dev` and left that tab's Qwen tree outside the new app. Those trees (pwsh 28756 and 29632) were the check's own and were stopped by PID.
3. **Each ended shell tab logged a 409 in the webview console.** The Resume bar (slice 6l2 Task 8) asked `/v1/sessions/<id>/resume-command` for every ended tab, and the core refuses a tab with no agent. Fixed in `e67695d`: the bar asks only for an agent tab, and a shell tab keeps "Resume runs PowerShell 7 in …". This is a component effect, so no Vitest test covers it. Checked live: no 409 after a reload, same bar text.
4. **In this Ubuntu, a WSL tab never shows a running command, so no agent's hooks can mark its row.** The distro's `/etc/profile.d/80-systemd-osc-context.sh` (newer systemd) turns `PROMPT_COMMAND` into an array and appends `__systemd_osc_context_precmdline`. That entry runs after `__marshell_prompt_end` in `crates/core/shell/marshell.bash` has cleared `__marshell_in_prompt`. The DEBUG trap then fires on it, sends `133;C` at every prompt and sets `__marshell_ran`, so the user's real command sends no `133;C`. The tab stays at the prompt (`sleep 15` showed "WSL, Idle"), and `Registry::mark_hook_agent` refuses a mark while `executed_seen` and the command is at the prompt. Cards still work, because permission requests don't need the mark. Slice 6j1's Noble rootfs had no such script. This affects Claude Code, Codex and Antigravity in the same distro just as much. Not fixed: it is outside slice 6l2, and is tracked in #85. It needs `marshell.bash` to ignore DEBUG traps from `PROMPT_COMMAND` entries after its own, or to keep its end hook last.
5. **A raw save of a CRLF file writes LF, and Review shows the whole file changed (220 lines).** The textarea gives LF, and the raw save writes what was typed. This is the same for every CLI. Not fixed.
6. **Qwen's `/theme` is blocked in a live check: "Theme configuration unavailable due to NO_COLOR env variable."** `NO_COLOR=1` is set in the tool process (not in the User or Machine environment), so it reaches the dev app and its tabs. Not fixed. `live-check.ps1 start` could clear it for the app.
7. **Qwen Code writes its own keys into the user settings: `"$version": 4` on its first save, and `ui.autoModeAcknowledged` in the distro.** Turning Marshell's hooks off removes only Marshell's entries, so a file Qwen has written since setup comes back without the hooks but not byte-equal to before setup. A setup and turn-off cycle with no Qwen run between is byte-equal. Expected, not a bug.
8. **Setup turned the one-line seed into an indented file (+109 −1).** The preview showed the whole file rewritten before Allow. Turning the hooks off keeps the new layout. Not fixed.
9. **The first "Allow once" click on the WSL card did nothing visible; the second answered it.** No request or log line showed the first click. Not reproduced, not fixed.
10. **The config review says "A backup is saved first, in ~/.marshell/snapshots/" even with a scratch `MARSHELL_HOME`.** That is fixed copy from before this slice. The setup card names the real folder (`…\lc-6l2-1\mh\snapshots`). Not fixed.
