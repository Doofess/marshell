## Findings

1. **The selected tab's end bar stood past the rounded shape.** The shared selected mark draws a straight 2 px bar on the end edge; on a tab with rounded corners it read as a caret beside the tab. Fixed in `d6d59ec0`: the tab clips its own box (`overflow: clip`), so the bar is cut to the shape. Test "cuts the selected mark's end bar to the tab's rounded shape" failed first. The user's picture shows no bar; it stays because the selected mark is the accessibility safety net's shape cue.
2. **A long path's parts ran over each other.** At 320 px, with a file three folders deep and its tools in the bar, the folders' names shrank into each other instead of scrolling: the reset gives a flex item a zero minimum. Fixed in `a73f68e5`: the path's parts keep their width (`flex: none`) and the path scrolls. Test "a path longer than the bar scrolls: its parts never shrink into each other" failed first. After the fix a tab opened with a path of 503 px in a 182 px bar is scrolled to its end (321 of 321).
3. **"Show file tree" from the palette left the tree without the keyboard.** In the narrow layout, with the keyboard in the editor, the command ran while the palette still held the keyboard, so the panel could not tell it had been in the file; the tree covered the file and the keyboard went to the terminal. Fixed in `74a8a334`: the command waits for the palette to hand the keyboard back, as the panels' own commands do. Test "the file tree's command waits too" failed first. After the fix the keyboard is in "Filter files"; run from the terminal, the tree shows and the keyboard stays in the terminal.
4. **The check started a Claude Code session by mistake.** A loop meant to pass onboarding pressed the launcher's "Start", which started Claude Code in the scratch default folder under the scratch `CLAUDE_CONFIG_DIR`. It was closed through the core's API at once, and the process tree held no `claude.exe` afterwards. Nothing was typed into it.

Seen and left as it was:

- **One panel at 1200 px with the sidebar shown is the narrow layout,** because the pane is 321 px there. The wide layout needs 480 px of panel.
- **A double-click on a tree row in the narrow layout opens a preview tab,** not a kept one: the first click shows the file and takes the tree away. A double-click on the tab keeps it. As before the slice.
- **Esc with the keyboard on Select region leaves to the terminal and select mode stays on.** The pane's own Esc, as before the slice.
- **The palette's chord does nothing while the keyboard is in the filter box,** as in any text field of the window.
- **Once the list is dropped, the mark and the help line stay hidden even where they alone would fit.** That is the order decision 3 gives.
- **In a right-to-left document a file's name is drawn tail first** ("ts.main") in the tabs and the tree. The app has no right-to-left language yet.
- **The Changes panel shows a scrollbar's thumb** when its list is longer than the panel. Outside this slice.
- The webview's console held two errors: the dev server's missing `favicon.ico`, and a 422 from a session the check asked for without `cols` and `rows`.
