## Findings

1. **The strip never drew a preview tab as one.** LiveApp's tab mapping left out the tab's preview flag, so the italics and ", preview" were missing. Fixed in `0b475840`, with a pin seen failing first.
2. **Beside the tree, an open file showed nothing.** The file's cell (`.files-body__content`) was a block, so each tab's body collapsed to 0 px. It is now a one-row grid, as `.side-pane__body` is. Fixed in `77a9104a`, with a `FilesBody.css` test seen failing first; the body was 652 px live.
3. **Showing a Files panel with no tab put the keyboard on the empty state's "Go to file…".** The tree is drawn in the first frame, but its rows only two frames later, once it is measured or after its first read, and `focusPane` took the first target it found. `paneFocusTarget` now waits while the tree has no rows, and `focusPane` gives a drawn tree up to 30 frames before it falls back to the empty state. Fixed in `f90122fd`, with three `focusPane` tests seen failing first; live, the keyboard landed on row `a`.
4. **In a checkout, Go to file and the content search went through the junction.** Git for Windows walks into junctions, so `git ls-files` and `git grep --untracked` listed 4,174 entries and 59 hits from the scratchpad through `up`. `under_plain_folders` (`server/files.rs`) now leaves out any file under a folder link, as the walk and the tree already did. Fixed in `5d45574f`, with `the_file_list_in_a_repo_never_goes_through_a_folder_link` (`tests/files.rs`) and `in_a_checkout_a_folder_link_is_not_searched_through` (`search.rs`) seen failing first.
5. **Enter on a content-search line opened the file at line 1.** The editor mounts one commit after its tab. React's dev double mount remade only the editor's view, and the tab's reveal effect went to the destroyed view. A production build would have scrolled but left the cursor on line 1. The editor now reveals its own `target`, keyed by line and column, and puts the cursor on that line (`lineOffset`). Fixed in `9bc5474a`, with "lineOffset" and "a line a tab was opened at" (`Editor.test.tsx`) seen failing first.

Not a product finding: keyboard input from outside the check reached the dev window once, a "?" in the filter and 22 Enters in `main.ts`. The user said the input was theirs. It was undone with Ctrl+Z before anything was saved.
