## Findings

1. **Open in system terminal opened nothing usable.** In run 2 the toast said "Opened in a system terminal." but the window closed at once: `std::process::Command` always hands the child the app's standard handles, and under `pnpm tauri dev` those are pipes to the log files. The console's PowerShell wrote its prompt into `dev.out.log`, and `claude --resume` saw redirected input and output, printed an error into `dev.err.log` and exited. Fixed in a994b7a: the console starts through `CreateProcessW` with no standard handles and nothing inherited, the program resolved on PATH and never in the current folder, out of the job when the job allows it. `start_gives_the_child_a_console_not_the_apps_handles` has the child write `[Console]::IsOutputRedirected`: `True` through `Command` under `cargo test`, `False` now. A profile whose program is a `.bat` or `.cmd` is refused for now ("batch files aren't supported"), because cmd's argument rules need std's batch escaping, which isn't ported.
2. **A session whose agent had ended still counted as running.** After `/exit` the tab's PowerShell lives on: the row read "Ended" from the SessionEnd hook, but `send` filled the shell's prompt, Open in system terminal answered "End the session first." and `list` showed `running`. Fixed in a994b7a (the user's ruling: an agent that ended is ended): one predicate, `SessionInfo::running`, used by the fill route, `marshell send` and `list`, both open-outside routes, History's Resume and the row menu. A later SessionStart makes the row running again. Failing first: `fill_refuses_a_row_whose_agent_has_ended`, `open_outside_opens_a_tab_whose_agent_has_ended` and `resume_goes_on_when_the_agent_in_the_tab_has_ended`.
3. **agy's first-run screen takes the fill.** Known limit, not fixed (decision 9): agy draws its prompt-like first-run screen before it is ready, so the fill lands there and is swallowed.
4. **The check's clipboard and focus are hazards to work beside it.** In run 2 the copied resume line appeared twice in session 4's Codex composer, at 02:36:06 and 02:36:15, with no one in the check pasting. Codex reads the system clipboard on Ctrl+V (a CDP Ctrl+V reproduced it), and the clipboard later held Vite build output that the check never copied, so someone was copying and pasting on the desktop while the focus test had left the dev window in front. Nothing was submitted. A check should minimise the dev window again after a focus test, and avoid leaving its own text on the clipboard.
5. **A check's Enter started a stray session.** In run 3, `marshell new` started session 1 while onboarding's "Start a session" form was showing. The check focused a terminal that was then replaced, and its Enter went to the form, which started Claude in the home folder (session 2, scratch config). The check's next keys answered that session's trust dialog, so the scratch `.claude.json` trusts the home folder. The session was closed with nothing sent to it. Lesson: confirm the focused terminal's session before sending keys.
6. **Two terminal views of one session.** Right after `marshell new` started session 1 from the CLI, the page held a second, hidden view of it (0 × 0, 10 columns) next to the visible one. It went away when another row was selected. Not fixed; worth a look in the next slice that touches the session view.
7. **A page reload, once.** In run 2 the webview reloaded at about 02:36:03, 4 s after Open in system terminal; the cause is unknown. Run 3 had one page load in its console log for the whole run, so it did not repeat.
8. **A pty WebSocket 404, once.** Run 1's first session got a 404 on its first pty connect (likely a race with the session's registration). It wasn't seen again in runs 2 and 3. The favicon 404 is benign.
