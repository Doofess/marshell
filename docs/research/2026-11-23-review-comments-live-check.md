## Findings

1. **"Add to send" on a resolved thread was undone without a word.** With the switch on, a resolved thread's menu offered "Add to send" and "Add your note…". Either said the comment was added, and GitHub's next answer dropped it, because a resolved thread leaves the send. Fixed in `4f34cc03`: both rows are off with "A resolved thread isn't sent. Unresolve it first." Test: `turns Add to send and the note row off for a resolved thread, with the reason`.
2. **A thread's label left the user's note out.** A thread's inside is hidden from a screen reader and its label reads it, but the label ended at the marks, so "Your note: …" was only drawn. Fixed in `4f34cc03`: the label ends with the note, cut at 200 characters like a comment's body. Test: `reads the user's note after the marks, cut at 200 characters`.
3. **A Copy that emptied the send left the keyboard on the page.** The Send bar goes when nothing is left, and the button the keyboard was on went with it. (A send into an agent moves the keyboard to the terminal, so only the copy showed it. Slice 6r-3's drafts had the same gap.) Fixed in `4f34cc03`: the keyboard goes back to the list. Tests: the two `backToList` tests.
4. **The comment box's hint kept the theme's grey in forced colours.** The box keeps its own colours there, and "Ctrl+Enter replies on GitHub · …" stayed `--text-3`. Fixed in `4f34cc03`: `CanvasText`. Test: `gives the box's hint line the system's text colour in forced colours`.
5. **A box opened at the list's bottom edge shows its text area but not what is under it.** The reply's error line and its button were below the fold until the list was scrolled; the error was announced. Slice 6r-3's draft box does the same. Not fixed.
6. **Resolving a thread that waits in the send drops it, and its note, without a word.** "Resolved the thread." is all that is said, and the Send bar's count follows. This is the plan's behaviour for a thread resolved on GitHub; when the user resolves it here, a word more would help. Not fixed.
7. **Not run:** "1 new comment on #1." (one account), a link's click (the system browser), "Replying…" across a session switch (no slow post to be had), the comment menu over a browser page, a send over the budget, and a real high-contrast theme and a screen reader, which are left for release sign-off.
