## Findings

1. **The onboarding frame grew taller than the window, so "Allow these changes" was out of reach.** A grid's auto row grows to its item, so the frame's `max-block-size: 100%` held only inside a row as tall as the content. Fixed in f131ae9: `.live-app__onboarding` gets `grid-template-rows: minmax(0, 1fr)`, tested first in `src/styles/dialogBodies.test.ts`.
2. **The Agents dialog had the same cause**: a long diff pushed Allow below the window. Fixed in c87c317 with the same row on `.agents-dialog`, covered by the same test.
3. **A reinstall's replaced Codex group was indented one level too shallow.** jsonc-parser's `replace_with` renders an object's inside at its parent's depth. Fixed in e17916c: replacing an object with an object now removes the old properties and appends the new ones inside the same braces, so the indent and any comments beside the group stay. Inserting the new group and removing the old one was rejected because it moved or dropped sibling comments. Test first: `set_replaces_an_array_element_at_its_indent`.
4. **Codex's shared app-server daemon sent a second tab's hooks to the first tab's row.** Codex 0.163 runs hooks inside a daemon that the first Codex in a `CODEX_HOME` starts, and the daemon keeps that Codex's environment, `MARSHELL_TAB_ID` included. Tab 5's "Wants to run `Set-Content out6.txt tab5`" appeared on codex-lc2's row, with its card and recap, and a Codex run by hand in a shell tab did the same. `--no-daemon` gave the right tab. Task 1's research ran every probe with `--no-daemon`, so it never saw this. Fixed in 0e4f3ca (decision 12):
   - Marshell starts every Codex tab with `--no-daemon`, after the program and any `resume` arguments (`codex_starts_with_its_own_app_server`, plus the updated argv tests).
   - The bridge drops the tab id when the nearest `codex` among its ancestors runs from Codex's `app-server-daemon` folder (`codex_daemon.rs`, with unit tests and `a_codex_event_from_the_shared_daemon_posts_with_no_tab`, `a_codex_permission_from_the_shared_daemon_prints_nothing` and `the_tab_stands_for_codex_without_the_daemon_and_for_claude`).
   - Checked again live: two Codex tabs, each asked to write a file, raised two requests, for `t2481f0173d01` and `tcd989def085c` respectively, and each row ended "Done". A Codex typed by hand in a shell tab started the daemon, reported to no tab, and asked in its own terminal.
   - The cost: Marshell's Codex sessions don't appear in Codex's own list of daemon sessions.
5. **A tab that first renders in the background gets xterm's late colour reply typed into its CLI.** When the tab is first shown, `]10;rgb:e5e5/e5e5/e5e5\]11;rgb:0000/0000/0000\` lands in Codex's composer, and one Enter submits it as a prompt. Seen for tabs created through the API and for a Codex tab restarted while another was shown; tabs started from the launcher while shown were clean. A pty WebSocket 404 also appeared right after an API create. Not fixed (decision 13): issue #60, and the pull request's Known limits.
6. **The first click on an unfocused approve card does nothing.** By design: "Buttons stay inert for 500 ms after the card gains focus". Here the hook then timed out and Codex asked in its own terminal. Observation only.
7. **The launcher's Start button can't be clicked with the mouse.** The terminal's `.xterm-link-layer` (z-index 2, inside `resume-pane__terminal`) wins the hit test, although the launcher paints above it. The keyboard works. Not fixed: it doesn't come from this slice.
8. **The Agents dialog says "Some hooks are missing" for an entry that was changed, not removed.** Copy only. Not fixed.
9. **Editing Rust during a check restarts the app and orphans its sessions.** `tauri dev` rebuilds on any change under `crates/`, so the app came back with a new PID and API port, and the old tabs' shells and Codex processes kept running outside the new app's tree. They were stopped by PID after checking they used the scratch home. Recorded in the live-check skill's rules.
10. **A Codex run by hand used the code-mode `exec` tool, and its approval stayed held after the turn ended.** Seen once, before finding 4's fix, from the daemon's wrong tab. Not seen again.
11. **A reinstall after a removal appends Marshell's Stop group after the user's, at a new position.** The empty `{"hooks": []}` that held Marshell's place isn't tagged, so Marshell doesn't reuse it, and the new entry needs trusting again in `/hooks`. The user's hook keeps its position and its trust, which is what decision 11 protects. The placeholder doesn't build up: a later removal drops Marshell's group outright, since nothing follows it.
12. **Resume and Restart start Codex with `resume --last`.** That picks the newest conversation in the folder, whichever tab ran it. Restarting two Codex tabs in the same folder resumed the same conversation in both, and Codex locked the second ("This conversation is open in another app"). History's link then followed the last tab to send a hook for it. Marshell resumes by id only for Claude Code, from before this slice. Now that Codex conversations are indexed, they could resume by id too. Not fixed: issue #61, and the pull request's Known limits.
13. **`live-check.ps1 stop` walked the whole machine once the recorded root had exited.** `Read-Record` reported the gone root with `Write-Output`, which became part of its return value, so `stop` walked the tree from PID 0. The idle process is its own parent, and the walk ended in a call depth overflow before stopping anything. Fixed in 8e6ac0b: the message goes to `Write-Host`, `Get-Tree` refuses PIDs 0 to 4, and the walk skips a process listed as its own child. Reproduced first with `tree` on a dead root, then checked with `tree` and `stop` on a dead root and `tree` on a live one.
