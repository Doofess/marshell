# Changes leftovers live check (slice 6u)

- Date: 2026-11-23, 13:33 to 13:48 local time.
- Build: `phase-6u` under `pnpm tauri dev` on Windows 11 Pro (26300). The dev build is not optimised, so its timings are slower than the release numbers in `2026-11-23-changes-big-checkout.md`.
- Home: a scratch `MARSHELL_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `USERPROFILE` and `MARSHELL_CLAUDE_SETTINGS`, with CDP on port 9333. Onboarding was left with "Skip: use limited status", so no hooks were installed. The real `~/.claude/settings.json` kept its modified time.
- Data: two small repositories made by a script (`repo-a` with three files in its diff, a tracked file with CRLF endings in the work tree and `core.autocrlf = yes` in the repository's own config; `repo-b` with one modified file), and the 20,000-file and 100,000-file checkouts from the measurements. For the first row the scratch home was seeded, with the app stopped, with a sandbox for a folder that was never made, one for an existing folder dated 8 days back, one for an existing folder dated now, a folder named like a sandbox with no `marshell-checkout` file, and a two-day-old `.empty-config.1-2.tmp`.
- Sessions: "Just the shell" PowerShell 7 sessions started by the check. No agent CLI ran.
- How it was driven: CDP evaluations and CDP keys in the webview only, no screenshots and no desktop input. The app was stopped once and started again with `restart` for the first row.

## Findings

1. **A new comment box opened without the keyboard when the kept draft sat above its row.** Enter on a row with a box open elsewhere keeps the first text as a draft. A draft above the row moves the row's index in the same draw, and the list took that for a key that moved the keyboard, so it focused the row again within its 200 ms window. A box asked for above the draft kept the keyboard, which is why the earlier checks missed it. Fixed in `fix(changes): a new comment box keeps the keyboard when a kept draft moves its row.`: the list leaves the focus alone while the comment box has it (`keyFocuses` in `DiffList.tsx`, with a test that failed first with "keyFocuses is not a function").
2. **On the 100,000-file checkout the notice "Looking for new files took too long, so some may not be shown." was up for most of the minute.** It showed with the first diff, went 27 s later, came back after 10 s and stayed for the 40 s that were left. Tracked files and their diffs showed throughout. A check that runs both the link safety check and the walk for new files needs about 2.1 s in a release build against the 2 s budget, and both come due every 10 s; the dev build is slower still, so the walk rarely finishes. Before this slice the walk alone took 2.56 s and never finished. Not fixed: the 20,000-file checkout of issue #176 shows no notice, and letting the two come due at different times is a change to the check's order that this slice didn't plan.
