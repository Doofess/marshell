## Findings

1. **The Settings switch for pull requests could not be turned off.** It announced "Show pull requests from GitHub: off" and stayed on, with the bar: the settings store compared only the two older Changes settings and dropped a change in this one alone, although the core had saved it. Fixed in `8f42480b`, test "reads pull requests as off after that switch alone was turned off" (failing first). Seen live: off, on, off and on again, the bar following each time.
2. **A branch switch that keeps the same commit left the previous branch's bar for up to 30 s.** `git switch -c` showed the old branch's pull request and buttons for 22 s: the panel recounted only when the commit changed. Fixed in `8f42480b` (the recount watches the branch and the commit), tests "changes with the branch when the commit stays the same" and "recounts when the branch changes, not only the commit" (failing first). Seen live: 2.7 s and 1.2 s.
3. **The method menu opened the Merge dialog while Merge was off.** Also the review's first finding. Fixed in `8f42480b`: no menu while the button is off; test "offers no method menu while Merge is off" (failing first). Seen live on the conflicting pull request.
4. **In forced colours the bar's note, reason and menus kept token colours.** The bar switched the system's forcing off for everything inside it. Fixed in `8f42480b`, test "lets the system force the colours of the notes, the reason and the menus inside the bar" (failing first). Seen live, emulated.
5. **The keyboard was on nothing while a pull request was being created.** Fixed in `8f42480b`: the "Creating the pull request…" line takes it; test "gives the line that says a pull request is being created the focus" (failing first). Seen live on #8.
6. **After a merge the keyboard was on nothing.** The button it came from goes with the next reply. Fixed in `8f42480b`: it goes to the bar; test "moves the keyboard to the bar when a merge took the button it was on" (failing first, a source check: the panel can't render in the tests). Seen live on #8, the keyboard on "#8 on GitHub".
7. **The same sentence showed twice in the bar** when a note was also the reason a button was off. Fixed in `8f42480b`, test "draws a sentence that is both a note and the reason once, and the button names it" (failing first). Seen live.
8. **A status that changes after every check has ended is seen at the next 30 s ask, not within 10 s.** By design: the bar asks every 10 s only while a check runs. Not fixed.
9. **"Pull request #4 was created." was said on returning to a branch** whose pull request had been made outside since the core last read that branch. True since the last look, but it was not created now. Not fixed.
10. **Draft and ready changes are not announced.** The buttons change; nothing is said. Not fixed.
11. **"Try again" after "The session moved to another folder…" can only repeat the refusal.** Not fixed.
12. **A palette command run seconds after a branch switch or a push answered from the reply the panel still held**, once with the old branch's line and once with "1 commit isn't on GitHub yet. Push it first."; a second try worked, and the core refuses anything that no longer fits. Not fixed.
13. **After "Hide" the keyboard is on nothing**: the button goes with the bar. Not fixed.
14. **With onboarding skipped, an ask was typed while Copilot CLI still showed its folder-trust question.** The same path as Send and Review, which wait for a ready agent only with full status. Not fixed here.
15. **A test of this branch needed Copilot CLI on the machine.** `ask_types_the_same_bytes_for_all_five_agents_with_no_enter` looked the agent up on the real PATH, so it passed on the dev PC and failed in CI with "Copilot CLI isn't installed, or isn't on PATH." The bar showed that failure for this pull request. Fixed with a stand-in path that no real program has; with no agent on the PATH the test failed the same way locally before the fix.
